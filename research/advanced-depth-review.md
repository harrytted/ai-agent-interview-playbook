# 工程进阶逐章深度复核

本轮以 `9fd516c` 为基线，完整复核18章工程进阶及对应Q057–Q110题源，实质补强其中17章；06章保留上轮已补齐的检索原理，不为制造改动重复扩写。三位负责人各审改六章，再轮换只读复核另外六章，主审汇总冲突、代码对应及独立计算。复核针对章节所声明的主题，不以字数、框架数量、案例复杂度或测试通过率判定知识深度。

## 读者应能推导什么

一个机制需要说明它处理的对象、输入和输出，内部计算或状态怎样变化，为什么需要这些步骤，以及结论在哪些条件下成立。案例用于检查推导，不代替推导；工程建议还要说明资源取舍和失败边界。通用算法、厂商接口、本手册选择的业务规则与本地实验能力分别标明。

## 跨章分工

02主讲重放与副作用的通用原理，16将其用于任务领取、取消和提交，17再处理事件确认与窗口。03主讲有限输入中的信息选择，06处理检索证据与父段展开；二者通过链接衔接。01负责单个控制器调度，07负责跨分支依赖、归并与协作收益。10解释推理与排队机制，16只把容量约束用于服务接收，避免重复推导。

每章已有配图继续只在主讲位置内嵌；题解以改变条件、解释边界和诊断错误检验知识，不复制整章机制。Q编号、题目标题和既有章节锚点需要保持稳定。

## 交叉复核发现后修正的细节

| 问题 | 修正 |
| --- | --- |
| 13的概念状态机比本地解析器更宽，遗漏连续块索引和后续消息增量 | 按源码说明串行块、连续索引、ENDING中的增量及唯一结束原因；完整生产配额仍列为设计要求 |
| 03的闭包候选可能为空或产生非正增量成本 | 比值计算前排除这些项，固定状态只计一次；过预算先拆步或缩小目标 |
| 04把read-your-writes误称为读后写 | 统一为写后读/读己之写，保留水位等待与未索引记录合并机制 |
| 03/04的“回到原文”可能被误解为禁止分层摘要 | 允许沿可靠依赖链回查具体源版本，禁止无法回查的摘要自证，与Q063保持一致 |
| 07重述前驱就绪与通用压缩推理 | 保留乱序、重投、改条件的分支验收，通用压缩原理链接03；独立题首次展开DAG |
| 10把缺字段笼统作为强模型升级理由 | 输入已有但抽取失败可升级；源输入缺失应澄清或补读，真权威冲突仍需裁决 |
| 12的DPO一步更新损失尾数不准 | 独立解析和中心有限差分复算，新损失约0.479589；策略梯度说明停止对给定return/baseline反传 |
| 16把本服务的持久接收约定概括成202的保证 | 按RFC 9110区分HTTP语义与本地接收账本提交后的返回行为 |
| 16的有限时间容量示例未充分区分近似和精确波次 | 流量差使用忽略起步与整数波次的近似，瞬时24项的六波另按固定耗时复算 |
| 17的确认位置、18的时间坐标容易混用 | 明确Kafka下一读取offset；拆分源媒体、播放、墙钟和单调时钟 |

## 验证记录

- 全仓306项单元测试通过；运行时、训练、配对评估、检索、协议、摄取、SQL、任务服务、事件、媒体和政策助手共11个实验入口执行成功。

- 110题编号和标题、18章原有Markdown标题锚点保持稳定；题页由源文统一生成。44张主图仍有44个作者内嵌位置，没有新增重复嵌入。
- MkDocs严格构建通过；站点检查覆盖204个HTML页面、45,363处本地引用和110篇独立题解。浏览器抽查训练公式、事件窗口表及多模态导航，核心推导可直接阅读。
