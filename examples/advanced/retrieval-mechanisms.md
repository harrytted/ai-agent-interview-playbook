# 检索机制实验：评分、候选损失与知识冲突

这个实验帮助回答三个原理问题：词项或向量分数怎样产生，正确证据在哪一阶段丢失，以及什么条件允许处理相互矛盾的记录。它不调用模型、不做自动分词，不提供 HNSW、IVF 或生产检索性能测试。

```bash
python3 examples/advanced/retrieval_lab.py --section all
python3 -m unittest discover -s tests -p 'test_retrieval_lab.py' -v
```

可以分别运行 `--section scoring`、`--section candidates`、`--section conflicts`。每节输出一行 JSON，`model_requests=0`；输入词项、向量、评测标签和事实记录都在[源码](retrieval_lab.py)中公开。

## 1. 从词项到分数

输入是已经手工分词的片段，不是原始中文。三段等长文本为 A=`hotel hotel`、B=`hotel form`、C=`policy text`；查询为 `hotel`。N=3，出现该词的片段数df=2，平均长度为2。

```text
idf = ln[1 + (N-df+0.5)/(df+0.5)] = ln(1.6)
score = idf × tf(k1+1) / [tf+k1(1-b+b×dl/avgdl)]
k1=1.2, b=0.75
A = ln(1.6) × 4.4/3.2 ≈ 0.646255
B = ln(1.6) × 2.2/2.2 ≈ 0.470004
C = 0
```

该公式采用 Lucene 的正值 IDF 形式和常见 BM25 词频项，但没有实现 Lucene 的分析器、字段、重叠词项或压缩长度范数，因此不把数值宣称为 Elasticsearch 的逐位复现。查询中每个不同词仅贡献一次，未实现查询词频权重。[Lucene BM25](https://lucene.apache.org/core/10_5_2/core/org/apache/lucene/search/similarities/BM25Similarity.html)

程序还分开控制两个因素：关闭长度归一化后，tf从1到2的收益大于2到3的收益；保持tf=1时，长片段受到长度项影响。先预测把b改为0后长短片段分数的关系，再运行函数复算。多出现一个词和多填一段无关内容，不能混成同一种改动。

查询扩展将 `hotel` 改成 `hotel lodging` 后，给定语料中另一段才获得词项命中。这只证明增加了匹配入口：多义词、否定条件和无关扩展也可能增加噪声，需要真实任务评测，不能由这两段文本宣布扩展有效。

向量部分直接给定 `(1,0)` 与 `(0.8,0.6)`，得到余弦0.8；没有声称这些向量来自语义模型。放大向量不改变余弦；内积排序与余弦排序的关系还取决于归一化，不能混用分数。[Faiss 度量说明](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances)

## 2. 融合和重排为什么可能仍缺证据

两路给定排名为 `[A,B,C]` 和 `[C,B,D]`，程序按 `1/(60+rank)` 计算RRF，得到 `C,B,A,D`。这是合并排名的方法，没有创造新候选，也没有判断文档的权威性。[RRF 定义](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

若问题同时需要A、C，而候选池只有B、A，即使离线核验器知道正确标签，把A完美移到第一位，证据召回仍为1/2。此时单题倒数排名RR可以从1/2升到1，**但两项证据仍不完整**；多题RR的平均才叫MRR。把C补入候选池后，标签排序的top-2才可能取得A、C。

`oracle_order`明确使用评测标签，只计算这个固定候选池的排序上限；它不是可上线的重排器。真实重排器需要根据问题与候选打分，不应读取测试集答案。这里的“证据齐全”也只检查给定标签是否出现，不证明回答正确、冲突已处理或语料中不存在未知反例。

另一个实验把三个给定向量的精确排序设为旧资料、不可见资料、有效资料。先取全局top-2再过滤，只剩空集；先约束合法域再做本例精确扫描，才取得有效资料。程序仅在本地教学数据中展示候选ID；生产路径不能把未授权内容或敏感候选信息发送给生成模型或外部重排器。

这个结果展示有限候选池的损失，不代表所有索引都按同一顺序执行过滤，更不能当成 ANN 参数测试。[pgvector 的实现说明](https://github.com/pgvector/pgvector#filtering)展示了近似索引过滤与迭代扫描的具体条件。ANN近邻重现率应对照同一合法域、同一度量的精确结果；业务证据召回率则需要独立相关性标注。

## 3. 条件不同、真冲突和证据不足

冲突实验的输入已经是结构化事实，不自动从自然语言提取矛盾。每条记录具有稳定ID、事实族、属性、适用对象和半开有效区间 `[valid_from, valid_to)`；可信宿主另外提供当前允许读取的ID。程序先匹配对象、属性、适用范围与业务日期，再处理优先关系。

| 条件 | 输出 | 原因 |
| --- | --- | --- |
| 普通员工，2026-10-31 | `supported: 600` | 只匹配旧版有效区间 |
| 普通员工，2026-11-12，两份同级有效记录给700和500 | `conflicting`，保留双方引用 | 相似度、上传时间和复制件数量均不决定胜出 |
| 同上，可信规则明确formal优先于faq | `supported: 700` | 对同一事实键应用明确的业务偏序 |
| 当前无权读取任何候选 | `insufficient` | 当前没有可用于支持回答的证据 |

优先关系由宿主明确提供，必须无环且只比较同一事实键与范围。程序计算传递关系，保留没有被更高优先有效证据取代的记录；剩余值相同则支持该值，多个值则保留冲突。坏的优先关系直接报错，不靠评分器悄悄消解。

这是一项教学合同，不是法律解释器或通用真相判定器。真实系统还需要可信的文档身份、来源级别、取代关系、单位与实体对齐、事实抽取和更新传播；没有检索到相反证据，也不意味着相反证据不存在。实验不连接本仓库知识摄取或任务服务的数据库。
