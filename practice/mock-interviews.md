# 模拟面试

## A 轮：基础与执行，45 分钟

| 时间 | 问题 | 观察点 |
| --- | --- | --- |
| 0–5 分钟 | 用一个做过的项目介绍自己 | 职责真实、背景简洁 |
| 5–12 分钟 | Agent 如何从用户请求到调用工具？什么时候结束？ | 模型/运行时/工具边界，终止与失败 |
| 12–20 分钟 | 同一工具调用成功后响应丢了，怎么办？ | 不确定状态、幂等、查询确认 |
| 20–30 分钟 | RAG 总回答错，如何一步步排查？ | 检索与生成分开评测，坏例证据 |
| 30–40 分钟 | 给现有教学实验添加一个失败场景 | 可复现的测试、明确的预期行为 |
| 40–45 分钟 | 你会如何选择模型与框架？反问面试官 | 有约束和测量，没有万能选型 |

追问链：怎么知道是这里坏了 → 能看到哪些字段 → 修好后怎样证明有效。不要让对话停留在工具名上。

## B 轮：系统设计，60 分钟

题目：设计内部知识库客服助手，检索当前员工有权限的文档；必要时创建工单；文档可能过期，工具可能超时。规模和 SLO 未提供，请先澄清再做显式假设。

| 时间 | 应讨论内容 | 需要留下的产物 |
| --- | --- | --- |
| 0–10 分钟 | 用户、敏感数据、读写操作、量级、可接受失败 | 需求与假设表 |
| 10–25 分钟 | 数据入库、ACL、检索、决策、写入审批 | 数据流与状态边界 |
| 25–40 分钟 | 超时、幂等、部分失败、恢复、取消 | 至少 4 个失败路径 |
| 40–50 分钟 | 开发集/保留集、质量/成本/延迟、灰度 | 指标定义、分母和发布门槛 |
| 50–60 分钟 | 预算变成一半，怎么改？项目风险与反问 | 一项删减与一项后续验证 |

不预设必须多 Agent、向量库或 Kubernetes。选用组件时解释它解决的实际问题。

## C 轮：项目深挖，30 分钟

围绕自己的一个真实项目回答：你交付了什么 → 当时最难的约束是什么 → 比较过什么方案 → 用什么数据验证 → 哪个失败案例还没有解决。没有生产数据时，明确说是个人实验及其数据量。

结束后使用 [复盘模板](review-template.md)，只选两个薄弱点作为下一次练习目标。
