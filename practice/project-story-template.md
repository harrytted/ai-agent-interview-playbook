# 项目表达模板

方括号均需要用自己的真实材料填写。没有数据就写“未测量”，不要把练习目标写成已经完成的结果。

## 60 秒介绍

我做的是 [项目/个人实验]，面向 [用户] 的 [具体问题]。我负责 [明确边界]。核心流程是 [输入 → 检索/决策 → 工具 → 输出]。最重要的一项取舍是 [约束、比较和决定]。目前用 [数据集与测试] 验证了 [结果]，还没覆盖 [限制]。

## 3 分钟 STAR

| 部分 | 填写内容 | 证据 |
| --- | --- | --- |
| Situation | 谁遇到什么问题，已有流程哪里不足 | 非敏感的需求描述或任务定义 |
| Task | 自己负责什么；目标与资源约束 | 任务边界与验收条件 |
| Action | 一个主要决策；备选方案；失败后怎样迭代 | 代码、设计记录、测试与 trace |
| Result | 实际测到什么；适用范围；未完成部分 | 命令、配置、样本量、运行记录 |

建议把时间主要留给 Action。

## 每个指标必须补齐

- 指标名称与分母：[例如成功任务数 / 全部有效任务数]。
- 样本与切分：[开发集、独立保留集、采样方式]。
- 环境与配置：[模型标识、版本、日期、数据版本、参数]。
- 基线与变更：[只改变了什么，未控制什么]。
- 结果与边界：[重复次数、波动、失败样例、未测项]。

例如“20 个自建样例中 16 个通过”可以描述一次实验结果，不能据此宣称生产准确率 80%。面试官追问时展示原始运行记录，说明自己和团队分别做了什么。

## 项目追问清单

为什么不用固定工作流？为什么这里需要 Agent？模型换掉会怎样？工具响应丢失怎么办？哪个指标最容易被优化错？权限在哪里校验？最坏失败是什么？如何暂停和回滚？如果重做，先删哪个组件？
