# Q091 GRPO 的组内相对奖励怎样计算，为什么标准化不等于完整训练？

**优先级：P1**

## 简要回答

原始 GRPO 用同题一组输出的奖励作比较基准，减少对单独价值模型的依赖。简化算例奖励 `[0,0,1,1]`，均值 0.5、总体标准差 0.5，相对值为 `[-1,-1,1,1]`。这只是相对信号，完整训练还需行为与当前策略概率、概率比、裁剪、正则和参数更新，并遵循具体实现的归一化。全组同分意味着缺少区分信号，不能推断所有损失项梯度都为零。



## 详细解析

先理解比较单位。原始设计对同一问题采样一组输出，让一条轨迹的奖励相对组内基线形成优势信号，而不是仅把绝对分数作为答案好坏标签。组内比较减少对单独价值模型的依赖，但仍需要正确奖励、可关联轨迹与行为概率。若任务初始状态或评分口径不同，分数差可能来自环境而非策略，需要把组定义与数据生成合同写清。

用一个简化算例复算：四条轨迹奖励为 `[0,0,1,1]`，均值为 0.5，使用总体标准差得到 0.5，每项减均值再除标准差，得到 `[-1,-1,1,1]`。它表示这组内部的相对位置。不同实现可能使用不同缩放、稳定项和归一化，因此示例展示计算直觉，不能把这四个数直接等同于所有框架的最终损失或完整优势实现。

真正更新参数还要知道哪些 token 是模型动作，计算相关策略概率与概率比，并结合裁剪、正则和归一化形成损失，再通过优化器更新。多次工具调用、不同输出长度和轨迹调用数都会影响信号分配。工具文本可以作为条件输入，但不能无差别参与动作目标。仅在 Python 中算出标准分，不意味着模型已经学习了任何行为。

同组全为零时，没有奖励差异可供这个相对项区分，但正则等其他项是否产生梯度需分别分析。应先检查任务是否过难、工具是否全失败、奖励是否只检查格式。若所有失败来自资料缺失，增加采样只会重复缺陷；若奖励可被无效引用骗过，训练可能强化投机。独立测试、奖励漏洞用例与过程证据应和分数曲线一起看。

## 常见追问

1. **总体标准差换成样本标准差数值一样吗？** 不一样。本题算例明确使用总体标准差；对齐框架时应查看实现，不能混用后声称复现。
2. **全组奖励相同就一定不更新了吗？** 只能说此相对信号没有差异；总损失可能含其他项，是否更新需检查实际计算图与优化步骤。
3. **奖励越复杂越好吗？** 未必。先保证可验证、与目标一致，复杂加权可能掩盖严重错误或提供可投机的捷径。

## 实战案例

教学案例以“带引用”为奖励，四条答案都附上无效来源却全得 1 分。处理时把证据支持与格式分开，验证器独立读取来源，并增加旧版引用和正确澄清样本。验收先复算相对值，再检查无效引用不能得成功奖励；本地实验只输出相对信号，模型是否更新必须在实际训练运行中另行证明。



## 常见误区

把组内标准化称为完整 GRPO；全组同分就断言全部梯度为零；忽略策略概率与 token 归属；只看训练奖励上升而不查奖励漏洞。
