# Q075 什么时候采用 Manager，什么时候采用 handoff？

**优先级：P0**

## 简要回答

先看谁负责下一步和最终答复。**Manager（主管调度）** 把专家当作有边界的能力调用，拿回结果后继续汇总；**handoff（控制权交接）** 让另一角色接管当前交互，继续向用户收集信息。独立上下文能减少过程信息进入主会话，却不自动隔离权限。我会先做单 Agent 基线，再根据任务独立性、上下文负担和交接成本决定分工，并给每次交接定义输入、产物、权限和返回条件。



## 详细解析

先把“需要更多知识”和“需要改变交互负责人”分开。政策比较由一个协调者统一交付时，可将地区研究交给专家，专家完成后返回结构化证据，协调者继续判断。用户从政策咨询进入申请办理，需要专员连续收集字段时，handoff 更自然。判断依据是控制权和对话责任，不能仅数模型实例；同一运行时通过持久状态切换提示与工具，也能实现交接。

委派前写清任务合同：原始目标、已确认事实、资料版本、可用工具、资源范围、剩余预算、需要返回的字段，以及何时报告缺口。专家结果至少包含结论、来源、适用条件和执行状态。协调者要能区分“已核对”“待补证”“工具失败”，避免把语气肯定当作任务完成。只给专家一个地区名称，通常不足以保证比较口径一致。

handoff 还要定义谁接收后续用户消息、哪些状态被保留、何时交回。交接摘要可以传递已确认事实，却不能把推断写成用户授权。申请专员接管对话后，提交仍需检查当前身份、对象权限和具体批准。控制权像值班安排，权限像门禁；换了值班人，门禁不会自然升级。

取舍要通过固定任务比较。独立研究可以并行，也能隔离中间工具输出；代价是多一次模型调用、摘要损失和协调延迟。简单的一次查询通常不值得拆成会议。先记录单 Agent 的失败类型，再用相近预算比较专家模式；如果收益来自更多尝试，应把预算差异一起展示。

## 常见追问

1. **子 Agent 有自己的循环，仍算工具模式吗？** 可以。内部多步执行不改变外部控制合同；若完成后回到主管，由主管决定答复，仍是主管调用专家。
2. **上下文隔离能防止专家越权吗？** 不能。还需限制执行器凭据、工具集合、存储命名空间和资源权限；少看消息不等于少拿权限。
3. **专家失败时主管应直接换一位吗？** 先按错误类型处理。暂时读取错误可有限重试，缺证据需补资料；盲目换专家可能重复同一缺口并消耗预算。

## 实战案例

教学案例中，主管比较两地差旅政策，另有申请专员。若两位研究专家直接和用户交谈，会重复询问出差日期。处理时让主管持有已确认日期，向专家发送相同口径；只有用户进入申请流程时才 handoff。验收检查研究结果都带同一日期与来源，申请专员能继续补字段，同时系统中没有未经批准的提交对象。



## 常见误区

把不同提示词数量当作协作能力；给专家一个“只读”角色名就认为权限已限制；把交接摘要里的“建议提交”误当成用户批准。

## 动手想一想

为“查政策→比较→申请”画两种控制流，各写交接输入、输出与终止条件。验收要求指出谁负责最终答复，明确一个应使用 Manager、一个应使用 handoff 的转折，并给出单 Agent 比较基线。
