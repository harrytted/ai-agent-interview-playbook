# Q098 删除、撤权和索引回退怎样避免旧内容再次被使用？

**优先级：P0**

## 简要回答

沿来源血缘处理原块、派生索引和缓存，并把当前使用资格作为查询与上下文组装的独立条件。旧索引快照只能提供历史内容，不能恢复已经撤回的权限或已删除资料。回退数据索引时保留当前访问目录，检查旧 pinned generation 与正常查询都受限制。配套实验验证新查询过滤，没有清除已返回文本、磁盘旧文件或外部模型上下文；真实服务要另外处理这些边界。



## 详细解析

删除和撤权改变的是当前可使用集合。原文件消失之后，向量、词项块、图关系、摘要和答案缓存仍可能携带内容，所以首先需要来源血缘列出受影响对象。图派生更新往往还会重建相关实体关系，不能假设只删一份原文就完成。[LightRAG](https://github.com/HKUDS/LightRAG) 可作为更复杂派生维护的选读实现。

配套实验通过最新 catalog 表示当前存在的文档版本及 principal 权限。省略于新完整清单的版本不再可查询，撤回 principal 后该身份不再有读取资格。词项索引提供候选，当前 catalog 决定候选能否进入结果；即使调用者指定旧 generation，也要经过当前目录。

**索引回退** 为了恢复一份可读的完整索引，不应同时恢复过期权限。实验的 `activate` 只改索引指针，保留当前 catalog。于是旧 generation 中虽然还保存着 v2 文本，删除 v2 后也不能重新返回；撤回 employee 后回退，admin 能读而 employee 仍不能读。

需要明确控制输入的权威来源。实验单写者将新完整清单视为可信授权更新，管理员再次提交允许 employee 的清单时会重新授权。若真实系统要防止旧资料清单覆盖新撤权，应把权限版本、来源新鲜度与授予规则分开管理；“回退不恢复权限”不是对任意后续重新授权操作的永久否决。

缓存与在途任务是另一层。已经返回的文本不会被远程收回，已进入模型历史的材料可能需要清理或阻止继续输出。生产系统应定义撤权何时生效，在查询、上下文组装和结果返回处核对必要资格，并记录不能清除的已披露范围。本地实验无外部缓存或模型会话，因此不能声称已验证端到端撤权。

## 常见追问

1. **保留旧 generation 是否违反删除？** 取决于删除合同。实验验证查询不可见，旧磁盘文件仍用于审计与回退；需要物理清除或保留期管理时要另行实现，不能把逻辑过滤等同安全擦除。
2. **如果撤权后又收到旧的允许清单呢？** 必须比较权限版本或可信事件顺序，不能让陈旧资料覆盖新授权状态。本实验只支持可信单写者顺序操作，未实现外部权限事件仲裁。
3. **新 Embedding 模型上线后能随时回退吗？** 还要保证旧读取器、向量维度、距离规则和数据仍兼容，且当前权限目录持续适用。参数维度相同也不表示两套模型向量可混用。

## 实战案例

先发布 700 元版，再更正为 720 元，随后撤回 employee。正常查询和指定旧 generation 都返回空；切回 700 元 generation 后，employee 仍空、admin 可读。删除 v2 的场景还保留 v1，因此历史日期有合法来源，新日期不凭旧文件补猜。验收检查当前目录修订号、查询结果和回退记录。



## 常见误区

只隐藏源链接；认为召回后不展示就不会进模型上下文；把索引和权限一起回退；用逻辑删除通过声称已经擦除所有副本。

## 动手想一想

发布两个 generation，撤回一个身份后指定旧 generation 查询，再回退。验收：旧索引不绕过当前访问目录；另写出外部答案缓存、已生成上下文和磁盘留存各需要什么额外处理，区分已实现与设计项。
