# Q077 多 Agent 怎样在失败、取消和高成本时收敛？

**优先级：P1**

## 简要回答

先按分支状态处理，不能把读取失败、证据冲突和完成混成一个成功。有限重试服从主任务预算与期限；取消后停止新派发，通知运行中分支，对已经提交的外部动作继续对账。判断是否值得多 Agent，要在同题、相近预算下比较最终质量、延迟与费用，并做消融。**多个角色互相赞同不代表独立验证**，仍需原始证据和校准过的评审。



## 详细解析

先建立可区分的分支状态：完成、可恢复读取错误、缺证据、需要澄清、取消中、结果未知等。协调者依据状态推进依赖，而不是等每位角色都发一句“完成”。暂时网络错误可以有限重试；政策条文互相矛盾需要核对版本，继续重复相同搜索不一定增加信息。允许部分交付时，要记录缺口；若完整比较是硬要求，则不能改口宣布完成。

全局预算与截止时间要传到各分支。派发前预留，已产生费用需结算，重试不能重新获得一整套额度。下游限流时减少在途请求并停止无关探索。集中协调方便管理这些控制，也会成为调度瓶颈；跨服务自治有价值时再采用更多去中心机制，同时付出重复消息、任务归属和终止检测的成本。

取消需要覆盖生命周期。先阻止未开始节点，再向运行中节点传播取消，区分“停止等待”和“远端已停止”。外部写入已经提交时，即使报告任务被取消，也要查询终态、登记操作 ID，按业务规则决定是否补偿。协议状态是调度线索，不能单凭 cancelled 字样断言远端没有副作用；受保护资源还要处理迟到请求。

收益评估看最终产物，不能把各分支得分相加。固定其余条件，去掉某分支或换成基线结果，观察质量、成本和延迟的变化。互评一致可能来自共享错误、相同资料或迎合评分规则，不能直接解释成独立支持，也不能由相同错误直接推断串谋。评分配置、文件与工具渠道要纳入控制，争议案例回到原始证据核对。

## 常见追问

1. **取消后立即返还全部额度吗？** 不能。已提交调用可能继续计费，应保留待结算额度，确认用量或终态后释放剩余部分。
2. **换不同模型评审就独立了吗？** 未必。它们可能共享来源、偏差或候选诱导；需要和人工及客观验证结果比较。
3. **多 Agent 比单 Agent 成功率高就该采用吗？** 还要核对预算、尝试次数和验收标准。收益可能来自多花调用，需报告成功成本及退步任务。

## 实战案例

教学案例三路研究中一路超时，一路存在版本冲突。用户此时取消，但上传 Worker 已提交请求。处理时停止新检索、通知其他 Worker，并沿原操作 ID 查询上传结果。验收应能看到取消后无新派发、已发生上传有对象记录、未知结果进入对账；单 Agent 对照表仍保留费用和最终质量，不以角色数量充当成果。



## 常见误区

收到取消就删除所有状态；把互相给高分当作交叉验证；只报告成功案例的耗时，遗漏失败、重试和协调开销。

## 动手想一想

为一条三分支任务画取消时序，分别在派发前、读取中、写入后取消。验收列出每个外部对象是否可能存在、哪些费用待结算，并给一个能检验分工收益的消融方案。
