# Q076 动态任务图怎样处理共享状态、冲突与迟到结果？

**优先级：P0**

## 简要回答

我会为任务节点设置稳定 ID、计划版本、依赖、预算和完成条件。结果返回时核对节点与版本，重复结果去重，旧计划结果不能覆盖新状态。共享证据可追加，最终报告由明确的所有者写入；Reducer 只定义数据怎样合并，不负责判断矛盾事实。重规划会生成新图，但节点循环、重规划次数和整个任务仍分别受停止规则约束。



## 详细解析

动态规划不是每次想到新步骤就随手追加一个任务。先给当前计划一个版本，为节点记录稳定身份、前置条件、输入资料版本、产物合同和状态。调度器只有在依赖满足、预算已预留、并发名额可用时才派发。这样一个节点的“完成”才有可核对含义，恢复后也能识别它是否已经执行，避免仅凭一段聊天记录重新安排所有工作。

新证据要求改变依赖时，先更新计划版本，再决定保留、失效或重跑哪些节点。例如统计口径从申请数量改成申请比例，旧数量结果仍可作为原始证据保存，但不能继续当作新比较结论。结果消息应携带任务与计划版本；迟到消息进入明确的归档或复核分支，不能按最后到达覆盖当前报告。

共享状态需要字段级所有权。研究分支可以追加带来源、版本和片段 ID 的证据；协调者负责最终综合。Reducer 可以实现追加、集合去重或特定覆盖规则，却不了解金额为何冲突。两个来源分别适用不同日期时，正确处理是保留证据并核对条件，而非用最大值、最新到达值或模型多数票替代事实判断。

DAG 只约束这一版节点之间的有向依赖，节点内部仍可能调用工具循环，重规划也可能反复产生新图。因此要分别限制节点步数、总重规划次数和全局预算。并行增加后还需背压：汇总方或下游服务处理不过来时暂停新派发。任务图负责“先做谁”，共享状态负责“保存什么”，两者都不能代替资源控制。

## 常见追问

1. **旧版本结果都要删除吗？** 不必。可保留来源与执行记录，供复核或重新计算使用；关键是不能未经验证进入当前结论。
2. **追加列表天然幂等吗？** 不是。同一消息重送会追加两次，应按稳定结果 ID 或来源版本加片段 ID 去重，并定义冲突处理。
3. **所有节点都成功就能成功交付吗？** 仍要验收综合结果。节点可能采用不同口径，或汇总遗漏必要限制；任务终态应由整体验收条件决定。

## 实战案例

教学案例先比较三地申请量，随后发现各地申请总量差异很大，计划升级为按比例比较。一个旧 Worker 晚到并写出“北湾增长最多”。处理时保留旧计数证据，阻止它覆盖新版比较，补齐分母后重新综合。验收注入同一结果两次及旧版本结果一次，当前报告应只使用新版口径，证据集合无重复，旧数据仍可追溯。



## 常见误区

把 Reducer 当成事实裁判；把 DAG 无环误解为整个 Agent 不会循环；重规划时不更新版本，导致迟到结果悄悄修改新结论。

## 动手想一想

写一张含三路研究和一次综合的节点表，再注入重复、迟到和矛盾结果。验收要求分别给出处理状态，不覆盖新版结论，并展示节点循环与整项任务的两个停止条件。
