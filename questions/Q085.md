# Q085 KV / 前缀缓存与检索、工具、答案缓存有什么区别？

**优先级：P1**

## 简要回答

它们缓存不同层次。KV / 前缀缓存复用模型已处理前缀的中间表示，检索缓存保存候选或排序，工具缓存保存读取结果，答案缓存直接复用交付内容。前缀缓存主要减少共享前缀的 prefill，新的 decode 仍要计算；不能说命中后整次任务免费。每层要按模型、参数、索引版本、时效和用户权限设计键与失效，尤其防止跨租户复用敏感结果。



## 详细解析

先问复用的是计算还是业务结果。模型 KV 保存 token 的中间表示，跨请求前缀缓存利用相同前缀省去部分重复处理；检索缓存则复用某查询的候选与排序。工具结果缓存可能返回某对象状态，最终答案缓存直接交付旧答案。前者通常仍要继续推理，后者可能省掉整条路径，正确性和失效条件因此明显不同。

以自动前缀缓存为例，主要收益在共享前缀的 prefill，新生成 token 的 decode 仍需计算。长输出、前缀重复少或缓存频繁逐出时，整体收益可能有限。稳定公共前缀有助复用，却不能为了命中率把不必要或敏感内容放进所有请求。PagedAttention 解决动态 KV 内存组织与碎片等问题，也不是保存上次完整答案，需避免把内存管理和业务响应缓存混成一件事。

再为业务缓存定义合同。检索键要考虑索引、过滤、有效日期和用户可见域；工具读取要考虑参数、对象版本和新鲜度；答案还依赖问题等价性、证据和业务规则。写入结果不能随意当作可重放的读取缓存。权限在读取原始结果和复用缓存时都要成立，文本相同并不证明两位用户有相同访问范围。

验证同时看命中收益与错误复用。固定任务后比较延迟、缓存命中、证据版本和质量，注入政策更新、权限撤销与租户切换。自部署缓存配置还要考虑占用、逐出和并发；托管计费需按相应合同理解，不能由计算复用直接推导免费。缓存是减少重复工作的机制，不是绕过新鲜度与授权检查的捷径。

## 常见追问

1. **查询字符串相同就能复用检索结果吗？** 不够，还需匹配索引、时间、过滤与可见域，或在复用前重新验证访问范围。
2. **前缀命中会提升 decode 吗？** 它主要省共享前缀处理，新 token 生成仍需计算；端到端收益取决于各阶段占比。
3. **缓存 key 带租户 ID 就完成隔离了吗？** 还要控制底层访问、更新与权限变化，检查键构造和所有复用入口，不能只靠一个字段名称。

## 实战案例

以下是固定教学预算，不是模型实测。串行关键路径为：排队400ms、prefill 600ms、检索100ms、decode 900ms，总计2000ms。前缀命中后prefill变为90ms，其他项不变，总计1490ms，减少510ms，即25.5%。不能把prefill的85%下降当整次任务下降85%。

| 变化 | 可选动作 | 判定 |
| --- | --- | --- |
| P17-v2仍有效、当前权限相同 | 按合同复用有效候选/读取结果 | 仍核对日期、来源与对象 |
| P17-v2已撤回 | 重查受影响资料并重建答案 | 旧答案不能因耗时短继续使用 |
| 只有前缀计算命中 | 继续当前证据检索与输出计算 | 命中不意味着答案已生成 |




## 常见误区

把 KV 当作完整答案缓存；认为命中就没有生成成本；只设置 TTL 不处理权限变化；把相似问题等同于可共享答案。

## 动手想一想

先复算1490ms，再将decode改为1800ms。合格答案得到新基线2900ms、命中后2390ms，仍省510ms，约17.6%；较好答案说明队列、工具和输出占比会限制整体收益。新条件：命中答案后发现权限已撤回，必须拒绝复用并重验，不能为满足耗时预算返回旧内容。分类知识回看Q064，本题重点是计算与失效决策。
