# Q015 什么时候值得使用多个 Agent？

**优先级：P1**

## 简要回答

先用单 Agent 或固定流程建立基线。若任务可以拆成较独立的子目标，需要隔离上下文或不同工具权限，多 Agent 才可能带来收益。成本包括任务分配、结果整合、重复工作和通信错误。是否值得，要看在相同验收规则下成功率、延迟与成本的变化，**不能从角色数量推断系统更聪明**。



## 详细解析

先建立单 Agent 或固定流程的基线，记录它为什么失败。某个独立研究任务需要大量中间材料、专用工具或单独复核时，拆分可能减少主上下文负担并提高并行机会。若只是把连续函数改叫几个专家，新增的分配、聊天和汇总往往没有解决原来的缺口。角色名称不能代替任务边界。

可拆任务要有输入、产物和完成条件。主协调者可以持有共同日期和人员类别，地区研究者各自返回来源、版本、条款和未知项，协调者再统一比较。子任务像委托一段可验收的工作，不能只说“研究一下”就等一段肯定结论。上下文隔离也不会自动限制权限，工具、凭据和存储范围应按任务授予，不能让每位研究者继承发布能力。

收益评估看最终产物。多个相似模型可能引用同一错误材料，相互赞同并没有增加独立证据；复核者需要明确的评分合同与可核对原文。成本则包括额外调用、摘要损失、重复工作、迟到结果和协调等待。固定任务与可比预算，比较成功、错误动作、延迟和费用，再通过移除某个角色检查贡献。多分支还需要统一预算、停止规则和失败收敛，否则每个子任务都觉得还能继续研究，主任务就很难真正结束。

## 常见追问

1. **独立评审一定比自己检查可靠吗？** 不一定。相似模型与共享来源可能有共同偏差，评审还会误读候选。让它对照原证据和明确规则，在人工标注与客观终态上校准，再判断减少了哪类错误。
2. **不同工具权限是否必须用不同 Agent？** 可以用任务范围、执行器与独立工具合同实现限制，多 Agent 只是组织方式之一。先看上下文和控制需求，权限始终要由可信服务落实，角色提示不能当授权凭据。
3. **怎样证明拆分值得？** 在同题、相近资源与同一验收规则下对照，报告逐题差异与退步；再去掉某角色或替换成简单基线，检查收益是否只是来自更多尝试，并统计整项任务成本。

## 实战案例

三地研究初版由主助手一次处理，长原文挤掉了比较条件。改为让地区工作单元返回统一证据合同，主任务保留日期、类别和综合职责；另设一种只压缩工具输出的单 Agent 基线。验收用相同任务比较来源覆盖、条件遗漏、错误发布与总费用，并让一路失败，检查缺口可见、重试受总预算约束。若简单基线已同样完成，就没有证据说增加角色更值得。



## 常见误区

把每个函数包装成一个“专家”，让简单任务被大量对话拖慢。多位角色共用高权限凭据，可能同时扩大错误影响；隔离消息不等于隔离资源。

## 动手想一想

对一个五步任务画单 Agent 与三 Agent 两版。验收：标出新增通信、可并行步骤以及需要什么实验才能证明拆分有效。再给三 Agent 版设计一次消融：去掉谁、其余条件怎样固定、哪些结果支持继续保留这个角色。
