# Q016 多 Agent 如何交接，冲突如何处理？

**优先级：P1**

## 简要回答

交接应像函数契约：明确目标、输入、约束、可用工具、预算、输出 schema 和完成条件。下游返回结论、证据引用、未解决问题与执行状态。协调者按预定义规则处理冲突，例如以最新有效版本或更高可信来源为准；无法判定就补充检索或请求决策，而不是按票数决定事实。



## 详细解析

先把交接对象做成可检查的任务合同。说明原始目标、共同输入、已确认事实、允许动作、工具与资源范围、预算、产物格式及终止条件。上游传递“请完成比较”不能自动赋予下游发布或付款权限；可信身份和能力范围仍由运行时传递与服务端检查。任务版本也应一起发送，防止旧计划结果混入新结论。

返回值要能用于下一步判断。除了结论，还应有来源 ID、内容版本、生效区间、适用对象、未解决项和执行状态。把“暂时没取到材料”与“有证据证明不允许”分开，协调者才能正确补查或结束。可以把交接想成带附件的委托单：表格字段帮助接手，附件是可回查依据；格式完整并不能证明结论真实，仍需核对内容。

合并先处理重复和口径，再处理语义。相同片段重送按稳定标识去重，不同金额要核对主体、日期和规则层级，不能让最新到达或多数投票直接裁决。来源相同的转载也不能当独立支持。无法判定时保留冲突并补检索或请求决策，最终报告由明确所有者写入。交接越精简越省上下文，却不能删掉限制与未知；整段历史全转发又会增加污染、敏感信息传播和成本，应先传必要状态与指针，按需回查。

## 常见追问

1. **下游需要发布权限，上游说同意够吗？** 不够。角色消息不是可信审批凭证，仍需检查用户、对象、当前授权和业务要求的具体批准。可以返回待发布草稿，由拥有对应能力的执行路径单独处理。
2. **两个 Agent 都引用了最新版，为什么还冲突？** 可能主体、人员类别、地区或生效日期不同，也可能一方误读条款。先对齐条件与原始出处，再核对是否真正矛盾；“最新版”标签本身不能替代有效区间判断。
3. **如何处理重复与迟到结果？** 结果带任务、计划和来源版本，重复按稳定标识处理；旧版本结果可以归档或重新验证，不能直接覆盖当前状态。重试追加列表也会重复，合并规则需明确去重与冲突分支。

## 实战案例

两位研究者对培训政策生效时间给出不同日期，一个读到公告发布时间，一个读到条款生效日。初版按两人的口头信心投票，报告取错日期。改为交回原文位置、版本、时间字段含义与适用范围，协调者按正式条款核对；未确认的条件保留为待查。验收注入重复证据与旧任务迟到结果，检查无重复计数、不覆盖新版报告；读取角色也不能因为交接消息写着“顺便发布”就生成外部发布对象。



## 常见误区

把完整历史无差别转发给所有 Agent，造成成本、污染和敏感信息传播。把摘要中的推测写成已确认事实，或把建议提交写成用户批准，会在交接时放大原始错误。

## 动手想一想

两个 Agent 对政策生效时间给出冲突答案。验收：用包含版本、来源、日期和置信边界的结构交接，说明如何裁决。再让一个来源撤回，说明哪些交接字段、比较结论和待发布草稿失效，如何保留其余有效工作。
