# Agent 工程进阶

<div id="agent-进阶课程"></div>

**深入长任务、系统设计、故障恢复与质量优化。**

在基础原理部分，助手已经能查政策、调用工具。现在任务变成“三地制度一起研究，等负责人批准，明天继续发布”。中间还会断网、换会话、改文档。任务一长，聊天记录就开始像塞满小票的口袋：东西似乎都在，要找时却翻不出来。

工程进阶部分沿着这些问题，解释怎样组织长任务、知识和工具，怎样从失败中改进，以及怎样在预算与权限范围内交付结果。每次引入一个组件，都要说明它解决了哪一个问题。

建议先读 [基础原理](../learning/README.md)，重点了解工具循环、RAG、状态、评测与可靠性。**每章先解释核心概念及其用途，再进入机制、图解、案例、推导与设计练习**，按章节顺序可以连续学习。章末的面试题用于闭卷检验和专题复习，不代替相关章节的正文。阅读官方文档时，优先追踪正文所解释的机制和产品边界，再学习框架接口。

## 一张学习地图

```text
基础：模型 / 工具 / 检索 / 状态 / 评测
                 ↓
运行基础：01 Harness → 02 持久执行 → 03 上下文 → 04 记忆与技能
                 ↓
能力组织：05 工具路由 → 06 Agentic RAG → 07 协作 → 08 编码与操作
                 ↓
质量闭环：09 评测 → 10 性能 → 11 安全 → 12 优化与训练
                 ↓
项目：任务合同 → 故障实验 → 逐题比较 → 版本发布
```

安全与评测也应贯穿前两段；分组用于安排学习顺序，实际系统不能等到最后才补授权和验收。

## 同一个案例，各章留下什么成品

继续使用基础实验中的两份住宿标准：海岚700元/晚，云洲650元/晚。每章完成物都可以与一项新条件对照，而不是只交一张抽象架构图。

| 章节 | 本章可读成品 | 改变条件后检查什么 |
| --- | --- | --- |
| 01–02 | 两地比较的交接包；工单崩溃恢复的意图、对象与恢复表 | 撤回证据重新打开工作项；崩溃后仍只有一个对象 |
| 03–04 | 压缩前后输入；事实修订与政策比较技能合同 | 未知项不丢失；旧有效期不被覆盖成永久事实 |
| 05–06 | 四工具目录与选择表；逐轮证据覆盖表 | 发现工具不等于有权限；证据冲突不被多数票掩盖 |
| 07–08 | 单流程/分支设计与共享预算；日期修复补丁；模拟页面前后样本 | 分支不各领一份总预算；UTC边界与对象核对有效 |
| 09–10 | 逐题配对评测表；关键路径与缓存失效表 | 发现退步任务；撤权使业务结果缓存失效 |
| 11–12 | 澄清/批准/接管待办；动作与观察分离的训练样本 | 改参数旧批准失效；成功文字不能骗过奖励 |

后文三地、四地或统计查询用于扩展设计，固定执行包只有海岚/云洲与文档/工单工具，不会凭空提供第三地或真实统计。新实验的可执行范围见 [政策实验](../examples/policy_agent/README.md)；图检索、真实多模型协作、浏览器操作、GPU服务和参数训练为设计或选读。各章会明确哪些是运行结果、哪些是手算或模拟成品，不因章节涵盖主题就声称完整服务已实现。

## 按目标选择主线

应用工程师先学 01–06，再用 09、11 建立质量门槛；确认单 Agent 的瓶颈后，再决定是否引入 07、08。平台工程方向重点串联 02、05、07、09–11，关注恢复、共享资源和服务边界。模型优化方向先完成 09，再学 12，并回查 03、08、10 中的输入、环境和推理约束。

这些路径共享同一套判断顺序：任务是否定义清楚 → 证据与工具是否正确 → 运行状态能否解释 → 行为是否满足验收 → 性能或参数还有什么瓶颈。不要用增加 Agent 数量代替错误定位。

## 学完一章，接着练对应的三道题

[36 篇进阶题文章](../questions/README.md#进阶系统)与 12 章一一对应，题号为 Q057–Q092。每题有口述短答、分节详细解析、带答案的追问、实战案例和验收练习。正文与对应面试题可以直接互相跳转。

读完相关章节后，先看题目并自己解释一次，再读分节答案。若只能原句复述，就把案例里的一个条件换掉：审批过期、远端结果未知、共享预算不足。回答会随条件变化，理解才算离开了背诵区。

## 从问题找到对应知识

| 观察到的现象 | 先检查什么 | 深入章节 |
| --- | --- | --- |
| 任务跑久后忘记进展 | 状态、摘要、交接信息是否完整 | 01、03、04 |
| 超时重试创建了两份对象 | 操作 ID、远端幂等、结果未知的恢复路径 | 02、11 |
| 工具越来越多却选不准 | 工具描述、检索召回、参数合同与路由数据 | 05、09 |
| 报告引用很多却答非所问 | 检索覆盖、证据支持、版本和适用条件 | 06、09 |
| 多 Agent 更慢、更贵 | 依赖、交接损耗、共享预算和关键路径 | 07、10 |
| 浏览器显示成功却没办成 | 页面状态、后端对象、观察与动作的关联 | 08、09 |
| 外部材料改变了工具行为 | 信任边界、授权执行点、数据出口 | 05、11 |
| 提示越写越长仍反复失败 | 失效分类、数据缺口与训练必要性 | 03、09、12 |

## 六周学习与项目节奏

| 阶段 | 阅读 | 本周产物 |
| --- | --- | --- |
| 第 1 周 | 01–02 | 运行时职责图；副作用前后崩溃的恢复表 |
| 第 2 周 | 03–04 | 上下文包；记忆更正与技能版本方案 |
| 第 3 周 | 05–06 | 工具合同；跨文档证据和追加检索策略 |
| 第 4 周 | 07–08 | 单/多 Agent 对照；隔离环境的操作记录 |
| 第 5 周 | 09–10 | 逐题评测表；延迟与预算实验 |
| 第 6 周 | 11–12 | 越权与奖励漏洞用例；改进和发布决策 |

每章先预测案例的失败方式，再读机制，完成设计练习，最后闭卷回答自检。将自己的决策、运行结果和失败原因记进项目笔记，逐步形成可复用的知识，而不是只收藏链接。[贯穿项目工作坊](project-workshop.md)把这些产物接成同一个项目。

## 三组能运行的进阶机制实验

在仓库根目录运行，Python 3.10+，只使用标准库：

```bash
python3 examples/advanced/runtime_lab.py --scenario evaluation
python3 examples/advanced/runtime_lab.py --scenario budget
python3 examples/advanced/runtime_lab.py --scenario replay
```

实验分别复算多次尝试指标与组内相对信号、验证预算预留与理想关键路径、模拟两个独立 SQLite 数据库之间的副作用后崩溃恢复。具体输入、预期输出和实现边界见 [实验说明](../examples/advanced/README.md)。
