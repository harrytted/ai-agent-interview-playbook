# 03 · 提示与上下文

**提示负责交代任务要求，上下文是模型这次调用实际能看到的全部信息。** 它包括提示、当前请求、可用工具，以及运行时选进去的状态和证据。资料留在数据库里、消息留在历史记录里，都要经应用选择和传入，才能供这次生成使用。

回答漏掉重要条件时，先看实际发给模型的输入。要确认条件有没有被检索到、有没有通过筛选，以及整理输入时有没有被删掉。

## 选择本轮输入

应用收到请求后，先确定本轮要做的事。再选出任务要求、已确认的状态、可用工具和必要证据。每一项都要服务于当前的决定。工具已经完成的动作，从可信回包或状态恢复。

把**指令、已知事实、待确认条件和外部内容**分开写。证据带上来源、版本和适用范围。任务仍缺少关键条件时，把它明确标成未知。

提示应写清交付目标、允许的动作和停止条件。权限、字段类型和写入前置条件交给程序检查。长期规则有更新时，记录本次运行实际使用的版本。

<div id="算例为政策助手分配预算"></div>

## 输入预算与裁剪

先按实际接口配置核对上下文上限和输出限制，再预留输出空间。工具声明、结构化字段和历史消息序列化后也会占用输入额度。发出请求前，尽量按目标模型的分词方式核算。

- **优先保留**当前目标、已确认的关键状态、必要证据和它的限定条件。
- **先移除**重复背景、失效资料、本轮用不到的工具说明。去重时保留能回查的出处。
- **必要证据仍放不下**，就缩小本轮任务范围，分段处理并保存已核实的结果。

裁剪时用完整条款或字段作为单位。日期、单位、否定词和例外条件一旦丢失，留下来的句子可能已经变了意思。长对话每轮都要重新核对优先级，最近的消息也可能只是重复信息。

<div id="证据进入上下文权限不能丢失"></div>

## 证据、权限和指令来源

权限要在内容交给模型前检查。身份来自可信会话，文档与工具服务检查当前用户对具体对象的权限。用到缓存、旧摘要和恢复记录时，也要核对现在是否仍可访问。

两条证据看起来冲突时，先对照对象、有效期和适用条件。然后检查来源以及取代关系。排序靠前只说明检索系统给了较高分。采用哪个结论，要以资料本身的适用性和权威性为准。

网页、文档和工具回包中的文本都按外部数据处理。标清来源有助于模型理解。执行器还要独立检查动作范围，避免其中的文字改变应用允许的操作。

<div id="摘要是有损转换结构化也会出错"></div>

## 摘要、状态与结构化输出

摘要会丢信息。压缩之前，先把用户确认的事实、工具核实的结果和未确认的推断分开。摘要里保留这种区别，也保留原始证据的定位信息。关键动作前重新核对重要字段。

**结构合格和事实正确要分别检查。** JSON 能解析后，还要验证必填字段和类型。然后核对引用是否真实存在、内容能否支持结论、状态是否与外部结果一致。越接近写入和对外发送，越应由程序核实这些条件。

## 按输入逐层排查

| 看到的偏差 | 先查哪里 |
| --- | --- |
| 需要的条件根本没进输入 | 状态读取、证据筛选、去重和裁剪。 |
| 模型把旧结论当成当前事实 | 状态版本、摘要的来源和材料的有效期。 |
| 字段齐全，结论却和资料对不上 | 字段背后的证据、适用范围和事实校验。 |
| 一处改动后结果变了 | 模板版本、资料版本、工具声明和实际发送内容。 |

保留足以复盘的输入记录。至少要能找回模板版本、所选证据和裁剪结果。敏感内容按权限控制，可以用证据编号定位。比较两版提示时，固定其他输入，用同一组任务检查改动的作用。
