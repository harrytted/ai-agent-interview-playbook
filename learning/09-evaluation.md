# 09 · Agent 评测

**评测先定义任务的成功条件，再用实际结果核对。** 一项任务可以跑多次。每次执行都是一次尝试，分别记录输入、使用的系统版本、终态、耗时和成本。

判断完成情况时，同时检查回答、证据和后端状态。语言流畅只说明回复好读。任务要求实际写入时，还要验证哪些数据发生了变化。

<div id="先定义成功再看演示"></div>

## 成功条件与评分

给每项任务写清楚可接受的终态、必须满足的条件，以及禁止发生的行为。信息不足时，合理澄清或等待可能就是当前阶段的正确结果。权限不足时，正确拒绝也应计入相应得分。

| 检查项 | 验收依据 |
| --- | --- |
| **任务结果** | 必要内容或目标对象满足要求。写入要到系统里核对。 |
| **证据** | 关键结论能在本次取得的有效资料中找到依据。 |
| **行为边界** | 没有越权、重复操作或未经批准的副作用。 |
| **终态** | 完成、失败、等待或未知，与实际结果一致。 |

越权、重复写入等硬性失败单列。即使其他项得分很高，也应按预先定义的规则判定这次尝试失败。超时和未知结果同样要记录，否则完成率会偏高。

<div id="把系统拆成可定位的指标"></div>

## 按执行链路定位问题

| 阶段 | 核对的记录 |
| --- | --- |
| **检索** | 文档版本、访问范围、候选与排序。 |
| **输入整理** | 证据是否完整进入模型输入。 |
| **决定与参数** | 选中工具、传入参数和校验结果。 |
| **执行与终态** | 操作编号、回包和实际对象的状态。 |
| **回答** | 关键结论、引用位置和证据的支持关系。 |

任务得分下降时，找第一次出现偏差的环节。轨迹记录可观察的输入、动作、观察和状态，用这些记录定位问题。日志里敏感正文按权限控制，必要时保留可回查的引用编号。

<div id="走一遍检索指标"></div>

## 检索指标

| 指标 | 衡量什么 |
| --- | --- |
| **Precision@K** | 前 K 项里相关结果的比例。常用口径以 K 为分母，约定好结果不足 K 项时怎么计。 |
| **Recall@K** | 前 K 项找回了多少已标注的相关资料。分母是该查询全部已标注的相关资料。 |
| **MRR** | 对每个查询，取首个相关结果名次的倒数，再求平均。没有命中记为零。 |
| **nDCG@K** | 按名次折扣累加相关性得分，再除以理想排序的得分。兼顾相关程度和排序位置。 |

首个有效结果靠前，MRR 就可能很高。需要多份证据时，还要看召回覆盖率。相关文档漏标，召回率就只能反映现有标注。没有可用证据的任务要单独验收澄清或拒答，也要声明零分母如何处理。

<div id="完成率成本与延迟也要写清口径"></div>

## 完成率、成本与延迟

**完成率先定分母。** 统计的是任务还是尝试，要写清楚。分别报告可答任务的正确率、不可答任务的处理结果，以及不同权限和任务类型下的表现。汇总时保留当前口径和样本数。

成本包括失败调用和重试。计算每个成功任务的成本时，用总费用除以成功任务数。成功数为零时直接报告总费用与结果。延迟分开记首个输出和完整终态。p95 用来看慢请求的整体水平，要注明起止点、采样范围和分位数算法。

<div id="数据集与评分器怎样不骗自己"></div>

## 数据集与评分器

开发集用于调整提示、工具、规则和评分细则。保留集用于检查调整后的效果。同源文档和近重复任务尽量按组拆分，避免同一信息同时进入两边。

后端对象、字段和权限可以先用程序核对。开放式回答可以交给人工，或用模型按评分细则辅助判断。评分细则描述可观察的通过条件。用人工标注检查评分一致性，也检查展示顺序和回答长度是否影响结果。

<div id="自检与参考答案"></div>

## 比较两个版本

用同一批任务做对照。固定资料版本、访问范围和评测口径。每次独立尝试前，把任务环境恢复到相同的初始状态。记录哪些任务由失败转为成功，哪些发生退步。

允许多次尝试时，看同一任务在 k 次中至少成功一次的比例（`pass@k`）。要求每次都可靠时，看 k 次全部成功的比例（`pass^k`）。比较时使用相同的次数和起始条件。

整体分数有变化时，再按失败类型回查。优先核对新版本是否改善了目标环节，以及是否引入权限、成本或延迟方面的退步。
