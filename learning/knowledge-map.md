# 先把知识连起来，再逐项深入

理解 Agent，不必先记一长串框架。可以沿一个问题逐步展开：模型怎样知道下一步做什么？需要资料或行动时怎样调用工具？信息和执行进展保存在哪里？任务变长后怎样安排步骤？有了这条主线，再看检索、协议、评测与工程机制，各自的位置就清楚了。

## 第一层：一个 Agent 怎样工作

[基础01 · 组成与协作](01-system-map.md)先区分单次调用、固定工作流和动态选择，再从模型、工具、记忆、规划四类常见能力讲起。这里先建立全景，不要求把每项能力做成独立模块。

| 你想弄清的关系 | 接着读 | 这一章多解释一层什么 |
| --- | --- | --- |
| 模型怎样从文字走到输出 | [02 模型原理](02-llm-primer.md) | token、注意力、自回归生成与训练/推理的区别 |
| 模型这一轮实际能看到什么 | [03 提示与上下文](03-context-and-prompts.md) | 问题、指令、状态和材料怎样进入当前输入 |
| 作出一次决定以后怎样继续 | [04 Agent 循环](04-agent-loop.md) | 观察、决定、执行与反馈如何反复衔接 |

模型原理解释“计算怎样产生输出”，上下文解释“这次提供了哪些信息”，循环解释“输出怎样推动后续工作”。它们回答不同层面的问题。

## 第二层：怎样获得信息、保留信息、组织行动

| 你想弄清的关系 | 接着读 | 与邻近概念怎样区分 |
| --- | --- | --- |
| 模型怎样使用外部能力 | [05 工具与 MCP](05-tools-and-mcp.md) | 工具是能力接口；Function Calling组织调用；MCP连接能力提供方 |
| 外部资料怎样成为回答依据 | [06 RAG 与检索](06-rag-and-retrieval.md) | RAG是一套检索并利用知识的过程，检索器可以作为工具被调用 |
| 过去的信息怎样影响这次任务 | [07 记忆与状态](07-memory-and-state.md) | 当前上下文、当前任务记录、跨会话记忆既有关联又有不同职责 |
| 多个步骤怎样形成整体 | [08 规划与多 Agent](08-planning-and-multi-agent.md) | 规划安排任务与依赖；多Agent增加分工与交接，二者不等同 |

例如政策助手通过检索取得制度原文，把选择后的条款放入当前输入；任务记录保存“已查哪座城市、还缺什么”；计划决定是否需要补查另一座城市。一个过程可以同时涉及检索、工具、状态和规划，不必把它硬归到唯一方框。

## 第三层：怎样判断它做得好，怎样处理不可靠

[09 评测](09-evaluation.md)先解释目标、证据与结果如何变成评价标准，再讨论数据集、评分器、成本和延迟。[10 可靠性与安全](10-reliability-and-security.md)进一步解释超时、重试、结果未知、幂等、授权和不可信输入。

理解正常过程以后，再追问“这里失败会怎样”，更容易说清失败发生在哪一层。这不意味着实际开发要到最后才考虑安全，而是阅读时先把正常机制建立起来。

## 题库放在哪里使用

基础原理与工程进阶两部分按章节完整讲解概念、机制、图解和案例；[110篇独立题目文章](../questions/README.md)按面试问题组织回答与追问。[题目与章节对照](../docs/question-index.md)帮助学习和复习往返定位：

- 基础01完整讲解定义、组成与协作；Q001从面试问题组织相应回答与追问。
- Q025–Q029聚焦工具执行与协议；Q030–Q032聚焦记忆和上下文。
- Q009–Q016聚焦循环、规划、协作与恢复；遇到术语先回到对应基础章。
- Q057–Q110对应18章工程进阶，每章三题，用于检查能否继续解释复杂条件。

第一次学习可以先读基础原理，再读工程进阶；复习时从具体题目进入，想看行为时再选做 [一次完整任务](00-first-agent.md)。这三种入口共享知识，不要求每次阅读都运行实验。
