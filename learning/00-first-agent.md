# 00 · 先走完一次 Agent 任务

小明问：“我在 2026 年 11 月 12 日去海岚出差，住宿每晚 650 元，超过普通员工上限吗？”先别猜答案。这个问题最适合用来观察 Agent 的基本机制：系统要取得制度、检查适用条件，再决定能否回答。

本单元面向会 Python 函数、字典和 JSON 的读者，默认只用 Python 3.10+ 标准库，无需密钥或网络。完成后，你应能解释模型和执行器的分工，指出工具结果何时成为下一轮输入，并改变一个条件预测行为。所有人名、城市、制度和金额均为虚构教学数据；这里只判断本例金额条件，不代表真实报销资格。

## 先建立一个工作定义

本手册用 **Agent 系统**指围绕目标、根据当前观察选择行动并接收反馈的系统。应用中的模型可以提出下一步，运行时负责检查、执行、更新状态和停止。模型生成 `search_policy(...)` 只是动作请求；Python 执行工具后取得资料，才有可用观察。

规划是安排下一步及其依赖，可以由模型承担，也可以由程序约束；长期记忆是跨任务保留信息的一种选择。本例先不引入独立规划器或跨会话用户记忆，仍能说明观察、决定、执行、反馈的关系。离线模式用有限规则代替模型，便于检查控制机制；它不展示真实模型的自然语言理解能力。[定义与复杂度取舍参考](https://www.anthropic.com/research/building-effective-agents)

[![G1：用户目标进入运行时，策略提出动作，运行时校验后调用工具，观察更新状态并进入下一次决定](../website/assets/diagrams/G1-system-flow.png)](../website/assets/diagrams/G1-system-flow.png)

读图时先找到三条不同的信息：用户目标、拟执行的动作、执行后取得的观察。可信身份由运行时提供，不由模型自行填写。问自己：“系统说了已完成，环境中应有什么证据？”在查询任务中是有效条款与正确比较；创建任务中还必须有真实后端对象。

## 两份资料，先手算一次

| 文档 | 生效区间 | 普通员工海岚每晚上限 |
| --- | --- | --- |
| 海岚旧版住宿标准 | 2026-01-01 ≤ 日期 < 2026-11-01 | 600 元 |
| 海岚新版住宿标准 | 日期 ≥ 2026-11-01 | 700 元 |

11 月 12 日适用新版标准，因此 650 ≤ 700，金额条件未超限。将日期改成 10 月 31 日，适用旧版标准，650 > 600。不能只看到“700元”就答可以；先确认对象、日期与来源。完整记录在 [政策数据](../examples/policy_agent/data/policies.json)，标准答案由 [独立期望](../examples/policy_agent/data/expected.json)保存，策略不能读取它。

## 正常路径：让工具结果改变下一步

在仓库根目录运行。`run-id` 标识一份保留的运行目录；重做时换一个新名称，不覆盖之前的证据。

```bash
python3 -m examples.policy_agent run --task 住宿金额核对 --mode offline --run-id intro-normal
```

这里应观察三个阶段：没有制度时提出检索；取得有效条款后比较金额；输出带证据的结论。先用下表阅读，再打开 `.local/policy_agent/intro-normal/trace.jsonl` 对照实际事件。下面是阅读提纲，并非供应商消息原文：

| 时刻 | 当前可见信息 | 下一步 | 为什么 |
| --- | --- | --- | --- |
| 检索前 | 海岚、11月12日、650元；没有制度观察 | `search_policy` | 回答需要外部证据 |
| 工具返回后 | 海岚新版住宿标准、有效日期、700元 | 比较并回答 | 必要金额证据已齐 |
| 任务结束 | 条款、比较结果、终态 | 不再调用工具 | 当前问答已满足验收 |

[![G3：模型或策略提出工具调用，运行时执行后将对应 call_id 的结果送入下一轮输入](../website/assets/diagrams/G3-tool-roundtrip.png)](../website/assets/diagrams/G3-tool-roundtrip.png)

图示的是应用侧工具执行后，再让模型依据结果回答的常见两轮模式；托管工具也可以在平台内部完成往返，多个工具调用可以共享一次后续模型输入。因此不能把图题理解为“每调用一个工具都必须额外发出两次 API 请求”。本节离线运行将图中的模型换成规则策略，模型请求数仍为0。

图中的“回填”是关键：工具结果必须关联原调用，并成为下一轮实际可见的信息。只把它写到日志、却不给策略看，下一步仍可能按旧前提走。离线策略的 [实现](../examples/policy_agent/policies.py)读取可见观察，不按任务编号决定答案。

金额主张校验后，程序用用户金额与有效上限计算并渲染比较结论，不直接信任模型自述“已完成”。正常回答应包含以下事实：日期为2026-11-12；海岚普通员工上限700元；依据新版住宿标准；650元未超过本例金额上限。`answered` 只说明这次查询已作答，不代表咨询工单已创建。

## 对照一份实际离线记录

一次正常查询可以按下面六步读：

| 顺序 | 发生了什么 |
| --- | --- |
| 1 | 建立任务，记录当前目标与条件 |
| 2 | 策略决定先查住宿标准 |
| 3 | 运行时检查参数与权限，开始查询 |
| 4 | 工具返回适用的新版住宿标准，每晚上限700元 |
| 5 | 策略依据查到的资料比较金额 |
| 6 | 核对回答与证据，记录任务结束 |

其中两次是策略决定：先决定查询，再决定回答。工具实际读取一次，没有调用真实模型，也没有创建工单。事件条数、决定次数和工具调用数表达的是不同事情。

这份提纲对应仓库保存的[完整运行记录](../examples/policy_agent/traces/normal/trace.jsonl)、[输入快照](../examples/policy_agent/traces/normal/context.json)与[结果](../examples/policy_agent/traces/normal/result.json)。这些产物来自离线教学运行；输入只包含本次实际取得的观察与有效证据，任务编号和标准答案不参与下一步判断。

## 改变条件一：删掉日期

先预测：能否直接套用最新制度？再运行：

```bash
python3 -m examples.policy_agent run --task 住宿金额核对 --variant missing-date --mode offline --run-id intro-missing
```

先查看当前的 `context.json` 与 `result.json`，再补充日期：

```bash
python3 -m examples.policy_agent resume --run-id intro-missing --reply-json '{"trip_date":"2026-11-12"}'
```

第一次应为 `clarification_required`，没有检索和写入。日期同时从问题和已知条件中移除，不能只删一个字段却让策略从原问题偷看。补充后从同一保存状态继续，累计预算不归零。`context.json`是最近一次快照，恢复后会更新；先读等待时的快照，再读恢复后的快照，观察未知日期变为已知日期。完整[补参记录](../examples/policy_agent/traces/missing-date/trace.jsonl)先保存等待状态，收到可信回复后才开始检索。

这是澄清，不是批准。用户告诉系统日期，只补足事实，不能据此授权创建工单。

## 改变条件二：搜索先返回旧版

```bash
python3 -m examples.policy_agent run --task 住宿金额核对 --variant stale-first --mode offline --run-id intro-stale
```

该变式模拟索引未更新。[实际旧证据轨迹](../examples/policy_agent/traces/stale-first/trace.jsonl)先返回旧版住宿标准；随后重新读取权威资料，取得适用的新版标准后再作答。对照正常路径，关键差异是新增观察导致新增查询。若工具始终没有当前材料，合法结束应是 `insufficient_evidence`，不能根据记得的标准答案填700元。

## 用独立评分检查，而不只看结尾文字

```bash
python3 -m examples.policy_agent eval --suite pilot --mode offline --output .local/policy_agent/pilot-report.json
```

试点包含以上三项，缺日期项同时检查等待和恢复。评分至少核对：事实和有效引用、是否真的取得引用、缺参前是否零调用、过期材料是否被排除、实际副作用是否为零。评分器从独立期望读取要求，不能让被测策略自报“全部正确”就通过。

运行目录保存 `context.json`（实际输入快照）、`trace.jsonl`（事件）、`result.json`（结果），评分另有报告。在线模式另需凭据，并单独记录协议、模型与实际用量；离线结果不代表模型能力。[实验入口与边界](../examples/policy_agent/README.md)

## 先预测，再揭晓

1. 将出差日改为10月31日，650元会得到什么比较结果？
2. 检索只返回一份无生效日期的“700元”摘录，够不够回答？
3. 用户只问金额，策略能否顺便创建咨询工单？

<details><summary>核对你的解释</summary>

1. 适用旧版住宿标准，金额上限600元，650元超过。先选适用版本，再比较。
2. 不够。缺少可核对的适用时间和完整来源，应继续核对或说明证据缺口。
3. 不能。问答与写入是不同目标；写入还需要具体草稿、可信批准和环境结果。

</details>

**完成标准：** 不看正文，画出一次工具往返，标明模型/策略、运行时、工具与状态；说清两个变式分别改变了哪个观察或未知项；引用一条记录解释为什么当前任务结束。只背出组件名还没有完成这次练习。
