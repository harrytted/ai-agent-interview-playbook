# Agent 基础课程

用户问“这笔住宿能报吗”，助手答得很流畅。你再看一眼：它读的是去年制度，员工类别还认错了。接下来该查模型、检索，还是工具？这门课就从这些具体问题走进 Agent 的内部。

先理解机制，再手算或运行一次，最后用面试题检查能否解释清楚。需要 Python 函数、字典、异常和 JSON 基础；概率和向量知识在算例中按需补充。知识点会陆续登场，不会让十个缩写先堵在门口自我介绍。

本课程面向 **AI Agent / 大模型应用工程师**。学完应能独立画出 Agent 的执行边界，解释 token、检索、记忆和工具的区别，为一次任务设计可验证的终态。

贯穿案例是内部政策助手：检索当前员工有权限的有效制度，回答条件是否满足；缺证据时澄清，必要时按流程创建咨询工单。

## 每一章怎样学习

1. 阅读机制前，先用已有理解预测案例下一步会发生什么。
2. 沿正文走完一个具体例子，自己检查输入、输出、状态和失败条件。
3. 做“动手验收”，留下一张图、一次输出或一条测试证据。
4. 闭卷回答自检，再展开参考答案；解释不清时回看相应机制。
5. 最后选关联面试题口述，把术语变成能迁移的知识。

不要只问“我知道这个词吗”，也要问“输入缺失、权限变更、工具超时以后，我能预测系统会怎样吗”。

## 两组可以亲手运行的实验

阅读本身不需要安装软件；脚本需要 Python 3.10+，仅标准库、无密钥、无网络。在仓库根目录运行：

```bash
# 手工数值：Attention、余弦、RRF、检索指标
python3 examples/foundations/math_lab.py --section all

# 行动边界：正常读取、有限重试、批准/拒绝写入、循环终止
python3 examples/agent_lab/lab.py --scenario all
```

第一组是 [数学机制实验](../examples/foundations/README.md)，没有模型或语义向量生成；第二组是 [执行器实验](../examples/agent_lab/README.md)，用固定脚本替代模型决策。二者分别验证数值定义和执行合同。真实模型的理解、规划与工具选择需要另做实际调用评测。

## 建议的四周节奏

| 阶段 | 阅读 | 验收 |
| --- | --- | --- |
| 第 1 周 | 01–03 | 画系统图、手算 Attention、制作上下文包 |
| 第 2 周 | 04–06 | 读 trace、写工具合同、融合两份检索排名 |
| 第 3 周 | 07–08 | 管理记忆版本、设计依赖图、说明协作成本 |
| 第 4 周 | 09–10 | 定义评测集、跑故障场景、做一次项目复盘 |

可按现有基础调整学习节奏。已有基础时可从自检开始，有缺口再回读。
