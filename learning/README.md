# Agent 基础课程

这是一条从原理走到工程的连续学习路径。先弄清系统怎样工作，再做数值实验、跟踪执行过程，最后用已有面试题检验能否解释清楚。需要 Python 函数、字典、异常和 JSON 基础；概率和向量知识在算例中按需补充，不要求先完成模型训练课程。

本课程面向 **AI Agent / 大模型应用工程师**。学完应能独立画出 Agent 的执行边界，解释 token、检索、记忆和工具的区别，为一次任务设计可验证的终态，并识别“教程演示”和“已验证能力”之间的距离。

贯穿案例是虚构公司的内部政策助手：检索当前员工有权限的有效制度，回答条件是否满足；缺证据时澄清，必要时按流程创建咨询工单。所有公司、规则和数值为教学材料，不是实际报销规则或作者履历。

## 每一章怎样学习

1. 阅读机制前，先用已有理解预测案例下一步会发生什么。
2. 沿正文走完一个具体例子，自己检查输入、输出、状态和失败条件。
3. 做“动手验收”，留下一张图、一次输出或一条测试证据。
4. 闭卷回答自检，再展开参考答案；解释不清时回看相应机制。
5. 最后选关联面试题口述，把术语变成能迁移的知识。

不要只问“我知道这个词吗”，也要问“输入缺失、权限变更、工具超时以后，我能预测系统会怎样吗”。

## 两组可以亲手运行的实验

阅读本身不需要安装软件；脚本需要 Python 3.10+，仅标准库、无密钥、无网络。在仓库根目录运行：

```bash
# 手工数值：Attention、余弦、RRF、检索指标
python3 examples/foundations/math_lab.py --section all

# 行动边界：正常读取、有限重试、批准/拒绝写入、循环终止
python3 examples/agent_lab/lab.py --scenario all
```

第一组是 [数学机制实验](../examples/foundations/README.md)，没有模型或语义向量生成；第二组是 [执行器实验](../examples/agent_lab/README.md)，用固定脚本替代模型决策。二者分别验证数值定义和执行合同。真实模型的理解、规划与工具选择需要另做实际调用评测。

## 建议的四周节奏

| 阶段 | 阅读 | 验收 |
| --- | --- | --- |
| 第 1 周 | 01–03 | 画系统图、手算 Attention、制作上下文包 |
| 第 2 周 | 04–06 | 读 trace、写工具合同、融合两份检索排名 |
| 第 3 周 | 07–08 | 管理记忆版本、设计依赖图、说明协作成本 |
| 第 4 周 | 09–10 | 定义评测集、跑故障场景、做一次项目复盘 |

这是学习安排建议，按现有基础调整；不代表完成时间或求职结果保证。已有基础时可从自检开始，有缺口再回读。

## 正确性怎样落实

GitHub 课程帮助发现主题，技术结论回查官方文档、协议和原论文。正文给来源、适用条件与核验日期；算法定义配可复算例；关键事实另做交叉审阅。具体记录见 [核验台账](verification.md) 与 [学习资源深度调研](../research/learning-resources.md)。

不能把“开源”“Star 多”“官方作者”或“测试全绿”当作全部正确的证明。课程示例会过时，术语也有不同约定。本仓库采用可追溯、可复算、可纠正的标准：证据不足的内容标为未确认，不把有争议的定义写成唯一标准，不把教学简化推成生产保证。

后续接入真实模型，可沿用 [7 天项目实验](../docs/engineering/08-project-lab.md)；需要数学、训练或推理系统更深知识时，再按 [调研报告](../research/learning-resources.md) 选修对应原课程。
