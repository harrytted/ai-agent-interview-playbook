# 学习路线与验收

如果希望从基础机制系统学习，先走 [基础原理（10 章）](../learning/README.md)，再用本页安排面试复习。各章含逐步案例与可复算实验，关联题用于学后检验。

已有基础时，沿 [工程进阶（18 章）](../advanced/README.md)与[54 道进阶题](advanced/README.md)逐章练习。总题库为 110 题；下面的 30 天路线先安排原有基础与工程题，进阶部分可以按工程进阶的六周节奏继续，不必把两份日程硬塞进同一天。

目标：能独立解释一个 Agent 执行过程，定位检索/决策/执行失败，完成一个有测试和证据的个人项目，并在追问中讲清自己的决策。

建议每天 45–60 分钟；进度按验收调整，不把读完章节当作掌握。基础要求是 Python 函数、异常、JSON、HTTP 和基本 Git；不会时先补这些，不必先学完整深度学习训练栈。

## 30 天路线

| 天数 | 学习与题目 | 动手产出 | 通过标准 |
| --- | --- | --- | --- |
| 1–2 | Q001–Q008，Agent/LLM 基础 | 画出模型、运行时、工具、状态的边界 | 60 秒解释 Agent；区分生成参数与执行动作 |
| 3–4 | Q009–Q016，编排与规划 | 运行教学实验；手画状态转移 | 能解释何时终止、重试和请求人工输入 |
| 5–7 | Q017–Q024，RAG | 手建 10 条检索样例，标注相关文档 | 分别定位“没检到”“证据无效”“答错” |
| 8–10 | Q025–Q032，工具/记忆/MCP | 给一个工具写输入、权限、错误合同 | 能区分 Schema、认证、授权和业务确认 |
| 11–13 | Q033–Q040，评测 | 建 20 条开发样例与一组独立保留样例 | 说明指标分母、数据切分和每次调用的成本 |
| 14–16 | Q041–Q048，可靠性与安全 | 制造超时、重复请求、恶意检索文本 | 没有未经确认的写入；没有无界循环 |
| 17–19 | Q049–Q056，系统设计 | 写一页设计：需求/数据流/状态/失败/指标 | 每个组件有目的；能删掉一个不必要组件 |
| 20–23 | 选择一个真实项目扩展 | 接入自选模型和自己的非敏感数据 | 记录版本与配置；区分 mock 和真实结果 |
| 24–26 | 项目测量与迭代 | 保留基线、一次改进、坏例与测量记录 | 指标可复跑；诚实描述未覆盖情况 |
| 27–28 | 两轮模拟面试 | 录音、自评分、追问后的修订 | 能在限定时间讲清机制与个人职责 |
| 29–30 | 到期复习与项目演示 | 5 分钟演示 + 1 页复盘 | 从空目录按 README 能跑通演示 |

## 7 天冲刺

| 天 | 当天优先事项 | 最低交付 |
| --- | --- | --- |
| 1 | 口述 Agent loop、ReAct、workflow、tool calling | 10 个术语各用一句自己的话解释 |
| 2 | RAG 链路与失败归因 | 一张检索链路图和 3 个失败样例 |
| 3 | 幂等、超时、人审、注入防护 | 跑完离线实验，并解释限制 |
| 4 | 评测、成本、延迟、trace | 指标定义表；没有数据的地方明确写未知 |
| 5 | 系统设计与技术取舍 | 45 分钟完成一个设计题 |
| 6 | 项目深挖模拟 | 3 分钟项目介绍 + 3 层追问 |
| 7 | 错题复习、演示、反问 | 完整演示与 5 个针对岗位的问题 |

时间不够时先练执行边界、RAG 评测、可靠性和项目表达；算法/训练岗位需要另补数学、训练、分布式训练和推理优化深度。

## 一次学习怎样算完成

1. 闭卷讲 60 秒：定义、机制、适用边界各一句。
2. 回答追问：失败发生在哪一层，拿什么证据确认。
3. 做练习：留一个测试、样例或设计决策记录。
4. 自评分并复习：能复述解析不等于能迁移到新场景。

## 框架学习顺序

先写一个有终止条件和工具校验的普通 Python 循环，再读 [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) 中状态、持久化和中断的概念。根据目标岗位再选一个框架深入，不需要同时背所有 SDK。框架版本与接口会变化，实践时应在自己的项目里锁定并记录版本。

## 面试之外的基本功

每周另留两次练习 Python 异步与取消、HTTP 超时、SQL、索引、事务、队列和并发控制。Agent 的外部工具仍然是普通软件系统，模型不会替代这些执行层的责任。

## 应用工程动手路径

基础工具循环之后可以直接学 [13 模型接入](../advanced/13-model-api-and-output-contracts.md)，再进入 [16 最小任务服务](../advanced/16-service-deployment-and-operations.md) 和 [14 知识摄取](../advanced/14-ingestion-and-index-lifecycle.md)。SQL分析是独立方向分支，不要求所有读者先掌握。任务与版本合同稳定后，再学事件订阅、媒体证据和实时播放。每步交付实际结果、失败轨迹和独立核验，具体顺序见 [应用扩充说明](../research/application-expansion.md)。
