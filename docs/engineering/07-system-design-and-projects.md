# 07 · 系统设计与项目表达

学习目标：从业务约束推导设计，并用真实证据讲清自己的贡献。下列场景、架构与数字是原创教学假设，不是公司的实际案例或个人履历。

面试时先用 1–2 分钟确认用户、动作范围、成功标准、数据规模、时延与风险，再画主路径，最后深入一个失败路径。下面的“回答”是起点，深入设计通常需要更长时间。

### Q049 设计一个企业知识库客服 Agent，你会怎样开始？

**优先级：P0**

**30–60 秒回答：** 先区分政策问答与修改订单。问答路径是身份解析、带权限的检索、证据筛选、生成并校验引用；没有足够证据则澄清或转人工。订单动作经过独立授权与审批，不能让文档中的文字直接触发。数据侧保存文档版本、有效期与 ACL，更新时重建受影响片段。评测同时覆盖正确回答、正确拒答、权限隔离和业务终态。

**工程追问与权衡：** 教学假设：100 万片段、每日 1 万次任务、目标 p95 小于 5 秒，均需用实测验证容量。关键词与向量混合检索是否值得，取决于专有名词、语义改写和延迟；固定问答流程足够时，不必增加自主规划。

**常见误区：** 先选数据库再问需求；给模型一个数据库管理员工具；删除原文却留下向量索引和答案缓存。

**微练习：** 画出身份服务、索引、重排、生成、订单工具、人工入口 6 个组件，沿“用户权限刚被撤回”的路径标出需要重新校验与失效的位置。

### Q050 设计一个可以引用来源的研究助手，怎么保证报告可信？

**优先级：P0**

**30–60 秒回答：** 先明确主题、截止日期与允许来源，再拆成可独立核验的子问题，设置搜索和抓取预算。保存原始出处、发布日期、抓取时间及可追溯片段；生成前合并重复与冲突证据，输出时把关键断言关联到能支持它的材料。搜索摘要只是候选线索，正文缺失就标记未核验。重要结论优先找一手来源，并区分事实、推断和未知。

**工程追问与权衡：** 多 Agent 可以并行处理独立子问题，但最终要统一时间口径、实体身份和证据去重。找到多个转载同一新闻的页面不等于多个独立证据。动态网页无法复现时，按允许的保存方式记录片段与校验值。

**常见误区：** 链接能打开就当作支持结论；把页面里的攻击指令当成研究要求；用搜索结果数量代表证据强度。

**微练习：** 为“某项目现在很热门”设计证据表，包含热度定义、采集时间、指标、局限。再写一个来源冲突时保留不确定性的句子。

### Q051 设计一个能创建、分派工单的 Agent，状态如何流转？

**优先级：P0**

**30–60 秒回答：** 输入先归类并提取必要字段，不足就澄清；生成可审核的工单草稿，通过身份、资源和业务规则校验后审批。执行器用稳定操作 ID 创建工单，保存外部工单 ID，再做受权限约束的分派与结果核对。超时进入待对账，拒绝审批则终止。创建成功、分派失败时向用户报告实际部分状态，不能重新创建一个工单来“重试全流程”。

**工程追问与权衡：** 可用 received→draft→waiting_approval→executing→succeeded 的主路径，另设 rejected、failed、unknown。这是教学状态机；实际拆分要看外部 API 是否支持幂等、查询和撤销。跨系统无法共用事务时，需要明确可补偿的动作及人工接管条件。

**常见误区：** 模型说“已分派”却没核对外部状态；一个 approved 布尔值跨多次修改复用；把回滚等同于删除已创建工单。

**微练习：** 对“创建成功，分派请求响应丢失”写排障步骤：查什么 ID、如何判定当前归属、何时允许再次分派、对用户说什么。

### Q052 面试官问“为什么选这个框架”，怎样回答？

**优先级：P1**

**30–60 秒回答：** 从需求与验证结果回答。短小、固定流程可以直接写代码；需要分支、持久化、人工暂停和恢复时，评估状态编排框架。列出最小候选，在同一任务集比较实现复杂度、可测试性、排障、依赖与运行成本，然后说明选型理由和退出成本。框架提供机制，权限、外部幂等和评测标准仍是应用职责。

**工程追问与权衡：** 不用“某框架已经成为行业标准”替代证据。适配层应隔离模型协议、工具与业务逻辑，但不要为假想迁移堆一套抽象。只有实际测过，才能说某候选在你的场景更快。

**常见误区：** 用 Star 数证明生产可用；声称用某框架就自动获得安全、可靠与可观测性。

**微练习：** 为“本地只读资料助手”和“跨天审批的退款流程”各写一份两行选型记录：最关键需求、最小实现、尚未解决的风险。

### Q053 怎样向面试官讲清一个真实个人项目？

**优先级：P0**

**30–60 秒回答：** 先讲用户与任务，再讲自己的范围、关键决策和验证证据。比如：“我做了一个离线工具循环实验，验证参数校验、步数上限和失败状态；工具选择由脚本模拟，尚未接入真实模型。”然后展示一个成功轨迹、一个失败轨迹及对应测试。没有用户和线上数据，就说个人实验，结果用可复现测试与明确的局限描述。

**工程追问与权衡：** 用 STAR 组织表达，但 Action 讲清“遇到何种证据→改变什么→如何验证”。团队项目列出自己负责的模块、协作与评审范围；开源参考写出处，不把下载运行说成独立设计。

**常见误区：** 把示例答案的“提升 30%”写进简历；把脚本模拟称为生产 Agent；用框架功能表代替自己的工作。

**微练习：** 按“我实现了___；证据是___；未实现___；下一步验证___”写 4 句自己的项目介绍，录音后让朋友连续追问两次。

### Q054 怎样解释指标提升，避免编造与夸大？

**优先级：P0**

**30–60 秒回答：** 说明基线、改动、固定数据集、样本数、运行版本、重复次数与指标分母。以教学算例为例：同样 50 题从 30 题完成变成 38 题完成，是从 60% 到 76%，提高 16 个百分点，相对提升约 26.7%。若未做随机实验，只能说该离线集合上的变化，不能直接声称线上业务增长。

**工程追问与权衡：** 少量样本的变化可能不稳定；展示逐题差异、失败类型、波动和反例，比一个小数点精确的均分更可审查。同时报预算、延迟和是否引入越权问题，避免只挑有利指标。

**常见误区：** 混淆百分比与百分点；A 用简单集、B 用困难集；调参时不断看测试集后继续称其为独立验证。

**微练习：** 写一行诚实的结果：“在___版本、___个___样本上，___从___变为___；尚未验证___。”所有空格填真实信息，没有测量的字段留为未测。

### Q055 Agent 项目怎样做测试，哪些该 mock？

**优先级：P0**

**30–60 秒回答：** 把确定性边界先测牢：工具参数、授权、预算扣减、状态转换、幂等与取消；用替身工具注入超时、重复响应和畸形输出。再做真实适配器的契约测试，以及小规模端到端任务评测。Mock 有利于复现控制流，却不能证明真实模型会选对工具、真实检索会召回，也不能替代第三方服务合同验证。

**工程追问与权衡：** 将外部副作用放在可隔离的测试环境；记录预期终态和禁止副作用。真实模型评测可重复多次观察稳定性，但必须记录成本。不要用同一段实现逻辑同时生成预期答案并判定通过。

**常见误区：** 单元测试通过就声称智能效果达标；只测试一次成功路径；只 assert 返回文本里有“成功”。

**微练习：** 为本仓库 [离线实验](../../examples/agent_lab/) 列一张“能验证/不能验证”表：各至少 3 项。接入真实模型后，补充工具选择与参数质量的独立任务集。

### Q056 线上突然回答变差，你会如何排查？

**优先级：P0**

**30–60 秒回答：** 先确认影响面、开始时间与风险，必要时回滚版本或降级为只读/转人工。固定一个失败样本与相应版本，沿输入、身份、索引、召回、重排、上下文、模型、工具和终态逐层找差异。优先检查最近变更与依赖故障，同时保留未受影响的对照样本。修复后跑回归集和故障场景，再小流量放量。

**工程追问与权衡：** “模型幻觉”是现象，不是足够的根因。检索缺文档、ACL 过滤过度、版本过期、截断证据和模型误用证据，应采取不同修复。没保存版本与足够观测数据时，明确无法复现的范围。

**常见误区：** 第一反应换更大模型；只改提示词掩盖数据同步失败；线上直接反复执行有副作用的失败请求。

**微练习：** 场景：“今天起退款政策回答错误，但搜索服务没有报错。”列出 5 个可区分的假设和各自一个检查证据，最后指定一个低风险回滚方案。

## 设计依据与核验边界

核验日期：2026-10-28。Q049–Q056 是综合工程原则设计的教学问题，不是收集到的真实公司面经；图示状态、容量与目标值需要由自己的实验验证。

| 设计依据 | 一手来源 | 已核验的范围 |

| 以任务和可检查结果构建评测 | [Anthropic Agent Evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) | 评测方法；不提供本文算例的实测数据 |
