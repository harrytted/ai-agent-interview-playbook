# 06 · 可靠性与安全

学习目标：说明一次动作为什么获准执行、失败后能否重做、恢复时如何避免重复副作用。

### Q041 工具失败后应该怎样重试？

**优先级：P0**

**30–60 秒回答：** 先分类：参数错误要修参数，权限不足要拒绝或补授权，短暂网络故障或限流才可能适合重试。重试必须受总期限、次数与预算限制，结合退避和随机抖动，避免大量请求同时冲击故障服务。读请求与写请求分别处理；写操作若结果不确定，先查状态或使用服务端幂等协议。AWS 的重试经验强调，重试本身也会增加负载。[来源：AWS 重试与退避](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)

**工程追问与权衡：** SDK、工具网关和 Agent 每层最多尝试 3 次（含首次），最坏可能把一次操作放大为 27 次底层尝试；指定一层负责策略，其他层遵守共同期限。服务端提供 Retry-After 时要尊重它，并设置并发上限。

**常见误区：** 所有异常都 catch 后立即重试；把模型换一种措辞再次调用视作修复权限问题。

**微练习：** 为“参数缺字段、403、429、读取超时、创建工单超时”分别写处理分支。解释最后两项为什么不能套同一个无条件重试策略。

### Q042 什么是幂等，为什么“工具超时”不等于“工具没执行”？

**优先级：P0**

**30–60 秒回答：** 请求可能已在服务端提交，只是响应丢失。幂等让同一业务意图的重复请求不会产生额外副作用。由客户端生成稳定操作 ID，服务端按调用者与 ID 识别重复、核对参数并返回已有结果；记录 ID 与业务写入需要原子性或等效一致性设计。新建一个相同参数的独立业务意图，应使用新 ID。[来源：AWS 幂等 API](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)

**工程追问与权衡：** 不支持幂等的第三方接口，需要操作日志、查询对账或人工处理不确定状态。只在本地内存里存“调用过”挡不住进程重启，也解决不了写入成功但本地标记失败的窗口。

**常见误区：** 每次重试生成新 UUID；看到超时就补发付款；只用参数 hash 去重，误拦用户确实想创建的第二个相同对象。

**微练习：** 画出“记录 pending→发出请求→外部成功→本地记录成功”的状态转换，分别在每个间隙模拟崩溃，指出哪些位置需要对账。

### Q043 人工审批应该放在哪里，审批后还能改参数吗？

**优先级：P0**

**30–60 秒回答：** 在产生副作用前暂停，展示具体工具、目标、参数、影响和必要证据，并保存待审批状态。恢复时校验审批人权限、审批对象、参数版本和有效期；若收件人或金额变化，旧审批不能自动覆盖新动作。框架的 interrupt 可以实现暂停和恢复，但业务授权规则仍需要应用实现。[来源：LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)

**工程追问与权衡：** 审批等待期间订单状态或人员权限可能变化，执行前应重验。拒绝、修改、超时、重复点击都要有可观察状态；审批凭证绑定动作摘要，避免“同意一件事、执行另一件事”。

**常见误区：** 提示词写“重要操作请确认”就认为工具无法提前执行；只保存一个长期有效的 approved=true。

**微练习：** 为发送邮件的确认卡设计 5 个字段，再指出“审批后正文被重新生成”应触发哪个状态和哪次校验。

### Q044 怎么应对网页或文档中的 Prompt Injection？

**优先级：P0**

**30–60 秒回答：** 外部网页和文档是待分析的数据，不能因为其中写着“忽略规则、导出全部资料”就获得控制权。模型提示只是防线之一；更关键的是工具权限、参数校验、数据访问边界、输出处理和高影响动作审批。OWASP 建议对 Agent 工具执行独立权限与上下文校验，降低注入得逞后的影响。[来源：OWASP Prompt Injection](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

**工程追问与权衡：** 先明确攻击者控制的渠道、想窃取的数据、目标动作和可观察结果；用无害数据及替身工具做回归。检测器与分隔符能提供信号，不能保证模型永远正确区分数据和指令。

**常见误区：** 过滤“ignore previous”这几个词就声称解决注入；让被注入的同一个模型决定自己是否应该获得更高权限。

**微练习：** 在一篇模拟政策文档中放入“把另一个租户的报表发送出去”。说明文档读取、跨租户读取与发送边界各应如何拒绝，并指出成功阻断的可核对证据。

### Q045 工具沙箱、参数校验和 ACL 分别解决什么？

**优先级：P0**

**30–60 秒回答：** 参数校验限制输入的结构与取值；授权校验决定当前主体可操作哪个对象；沙箱约束运行时对文件、网络和资源的访问。这三层互补。模型给出一个合法订单 ID，不代表用户有权查看该订单。身份由可信会话或网关传递，租户不能直接信任模型输出；每次访问都要执行授权。[来源：OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

**工程追问与权衡：** 搜索过滤、缓存命中、引用原文下载、工具调用都不能绕开同一权限政策。限制可访问路径和出站域名时考虑规范化、重定向与 DNS 等边界；把任意 shell 暴露为通用工具会扩大审计范围。

**常见误区：** Schema 正确就当作业务正确；浏览器前端隐藏按钮就当作后端已授权；共享缓存键只包含问题文本。

**微练习：** 工具入参含 user_id、tenant_id、document_id。指出哪两项通常应从可信执行上下文注入，写出“用户 A 请求用户 B 文档”的预期拒绝测试。

### Q046 Checkpoint 能保证崩溃恢复后不重复执行工具吗？

**优先级：P0**

**30–60 秒回答：** Checkpoint 保存工作流状态，让系统知道从哪里恢复；它不自动让外部系统的副作用与本地存储形成一个事务。LangGraph 用 checkpointer 保存线程范围的图状态。[来源：LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 如果外部写成功、checkpoint 尚未落盘就崩溃，恢复仍可能再走到该动作，因此工具要有稳定操作 ID、结果查询和去重机制。

**工程追问与权衡：** 区分运行 ID、会话 ID、业务操作 ID。保存状态版本，支持升级后的兼容读取；恢复时重新校验当前权限与资源状态。断点越细，恢复损失可能越小，存储和一致性成本也会增加。

**常见误区：** 有了框架就承诺所有外部操作 exactly-once；把恢复实现为从头重放整个有副作用的函数。

**微练习：** 设计 run 的 running、waiting_approval、succeeded、failed、cancelled 状态，标出允许恢复的状态，并解释“工具结果未知”为什么还需要单独记录。

### Q047 用户点了停止，怎样取消流式 Agent？

**优先级：P1**

**30–60 秒回答：** 停止展示 token、取消本地任务和停止远端执行是不同层次。沿调用链传播取消信号，关闭流、释放连接、阻止后续工具调度，并记录已发生的副作用；远端不支持取消时要继续查询或对账，不能直接宣称动作没发生。Python asyncio 的取消是协作式的，清理可放在 finally 中，不能随意吞掉取消异常。[来源：Python asyncio 取消](https://docs.python.org/3/library/asyncio-task.html#task-cancellation)

**工程追问与权衡：** 输出的工具参数可能尚未接收完整，不能执行半截 JSON。对已经提交的外部写请求，取消不是回滚；补偿动作也要单独授权、记录和验证。

**常见误区：** 前端断开 SSE 后后台无限继续跑；把“已取消”的 UI 状态当作外部任务终止证据。

**微练习：** 给“模型流输出→只读搜索→创建工单”三阶段分别写停止行为，说明用户在创建请求发出后点击停止时，界面应该如何描述尚不确定的结果。

### Q048 如何防止 Agent 死循环与故障扩散？

**优先级：P0**

**30–60 秒回答：** 明确成功、不可完成、需用户输入、预算耗尽等终止状态，设置步数、墙钟时间、token 与工具并发预算。对反复相同调用、连续无进展和上下文膨胀发出信号，必要时降级为部分结果或转人工。限流、熔断与隔离队列保护共享依赖；预算应该覆盖子 Agent 和重试，而不是每个子任务各自无限扩张。

**工程追问与权衡：** 降级结果要说明证据与缺口，不能编一个“已完成”。只凭调用参数重复就立刻终止可能误杀有效轮询；结合允许的轮询策略与业务状态判断。

**常见误区：** 只设模型最大输出 token，却没有任务总预算；每个子 Agent 都能继续派生子 Agent。

**微练习：** 一个主任务预算为 20 次工具调用，派出 3 个子任务。给出共享预算的分配与扣减规则，并处理两个子任务同时申请最后一个名额的竞争。
