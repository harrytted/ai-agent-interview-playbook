# RAG 与检索诊断

目标：把“回答错了”拆成可定位、可实验的问题。以下指标计算必须声明评测单位、相关性标注与样本来源。

### Q017 一个 RAG 系统的完整数据流是什么？

**优先级：P0**

**30–60 秒回答：** 离线侧解析文档、保留元数据、分块、建立索引；在线侧理解查询、执行权限过滤、召回候选、可选重排、组织证据、生成答案并验证引用。RAG 的关键是让生成过程使用外部材料，而不只是调用向量库。解析丢表格、索引过期或生成误读都可能让最终答案失败。[RAG 起点](https://arxiv.org/abs/2005.11401)

**追问与权衡：** 现代工程里的“RAG”比原论文架构更宽泛，应区分原始方法与一般检索增强管线。

**常见误区：** 没搜到就让模型凭记忆给出精确内部政策；没有可验证证据时应限定回答范围。

**微练习：** 画出一份 PDF 到带引用答案的路径。验收：每个阶段都有输入、输出、版本标识和至少一种失败信号。

### Q018 Chunk 大小和重叠该怎样选择？

**优先级：P1**

**30–60 秒回答：** 分块要尽量保存完整语义单位与定位信息，例如标题、条款、表格行及其表头。过小可能断开条件与结论，过大可能稀释主题、占用上下文。先依据文档结构建立基线，再在代表性查询上比较检索与回答结果；重叠可以降低边界丢失，却增加冗余。没有通用的最佳字数。

**追问与权衡：** 先用较小块检索，再带回父段落是一种候选方案，但扩展上下文也可能引入过时或无关条件，需要单独评测。

**常见误区：** 拿英文 token 参数直接当中文字符数；把所有表格拍平成无表头字符串。

**微练习：** 将“仅试用期员工不可报销，转正后适用”从中间切开。验收：展示错误检索如何发生，再设计保留条件的分块方式。

### Q019 为什么向量检索和关键词检索可以互补？

**优先级：P0**

**30–60 秒回答：** 关键词检索擅长保留精确术语、产品编号等匹配信号；向量检索能表达部分语义相近关系，但可能混淆相近编号或否定条件。混合检索先分别召回，再去重和融合。分数尺度不一致时，可以使用基于名次的 RRF；它是可验证的基线，并非对所有查询必胜。[RRF 公式](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

**追问与权衡：** RRF 形式为 `Σ 1/(c+rank)`，`c` 是平滑常数。具体值和候选窗口仍要结合任务验证。

**常见误区：** 直接把两种未校准分数相加；只有向量分数高就认定证据可靠。

**微练习：** 两路结果分别为 `A,B,C` 与 `C,A,D`，取 `c=10`。验收：算出 A 与 C 的融合分，说明未出现的文档如何计分。

### Q020 召回和 Rerank 为什么分两阶段？

**优先级：P0**

**30–60 秒回答：** 第一阶段从大语料中快速找到较多候选，第二阶段用更细致的相关性模型对候选排序。重排只能处理已经入选的材料，关键证据没召回就无法被排到前面。先观察召回覆盖，再看排序质量和最终上下文是否保留必要条件；增加重排器之前，要算额外延迟与每次请求成本。[Sentence Transformers 两阶段检索说明](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

**追问与权衡：** 候选数越大，重排成本可能越高；上下文预算有限，最终选取还要考虑重复和证据多样性。

**常见误区：** 把 rerank 当成事实核验，或认为它能补出不存在的文档。

**微练习：** 构造一个目标文档不在 Top-20 的查询。验收：解释为何更换 Top-20 内部排序无法解决，以及先改哪一阶段。

### Q021 向量索引如何兼顾延迟与检索质量？

**优先级：P2**

**30–60 秒回答：** 精确搜索逐个比较，适合作为质量基线；近似最近邻索引用一定召回损失换取效率。以 HNSW、IVFFlat 等实现为例，索引与查询参数会影响速度、内存、构建成本和召回。应在真实过滤条件与并发下，比较近似结果对精确结果的覆盖，同时单独看业务答案效果。[pgvector 索引说明](https://github.com/pgvector/pgvector#indexing)

**追问与权衡：** 过滤条件可能改变有效候选数量。查询很快但租户内只返回少量结果，可能是过滤与近似搜索组合造成的召回问题。

**常见误区：** 将“向量库支持过滤”直接等同于“任何权限条件下召回都不变”。

**微练习：** 同一批向量用精确与近似查询各取 Top-10。验收：明确 tie 处理，统计重合率，再增加严格过滤重新测量。

### Q022 ACL 应放在哪里？文档更新和删除如何传播？

**优先级：P0**

**30–60 秒回答：** 访问控制由可信身份与服务端策略决定，应在证据进入模型上下文前生效，生成后再过滤无法撤回已经泄露的信息。索引需保存文档 ID、租户、权限、版本及生效状态。更新时切换有效版本；删除时清理原文、分块、索引及相关缓存，并处理已排队请求。具体一致性目标要明确记录。

**追问与权衡：** 索引尚未同步时，可用源系统权限复核或暂时拒绝敏感查询。高可用不能成为放宽权限的理由。

**常见误区：** 让模型根据“这份文件是否机密”自行鉴权；只删原始文件而保留可检索块。

**微练习：** A 用户失去文档权限时，列出所有可能残留证据的位置。验收：包括结果缓存、会话上下文和摘要，不只包括向量索引。

### Q023 RAG 如何评测，Recall@k、MRR 和答案质量有何区别？

**优先级：P0**

**30–60 秒回答：** 检索指标衡量证据是否进候选、排得是否靠前，回答指标衡量结论正确性、证据支持和引用。若标注了每个问题的全部相关文档，Recall@k 是 Top-k 中相关数除以全部相关数；MRR 平均首个相关结果名次的倒数。两者都不能直接当作答案正确率。评测还应覆盖无答案、过期政策和无权限样本。

**追问与权衡：** 不完整标注会影响 Recall 的解释。使用模型裁判应抽样人工核查，记录评分规则与裁判版本。

**常见误区：** 将“Top-k 命中一个答案文档的比例”不加说明地写成完整 Recall；在调参集上反复优化后仍称为独立测试。

**微练习：** 共四个相关文档，Top-5 命中两个，首个在第三位。验收：算出 Recall@5=0.5、该查询 RR=1/3，并解释仍可能答错的原因。

### Q024 RAG 回答错误应该按什么顺序排查？

**优先级：P0**

**30–60 秒回答：** 我先确认权威答案与用户权限，再沿数据链路找最早偏差：源文档是否正确有效，解析与分块是否保留关键条件，索引是否更新，目标证据是否被召回和选入上下文，最后检查模型是否误读或引用错位。每次只改一个关键因素做对照，保留原始失败样本作为回归集。

**追问与权衡：** 可以用人工正确证据替换检索结果做诊断实验。如果仍答错，优先检查提示、上下文冲突或生成能力，而不是继续调向量索引。

**常见误区：** 一出错就更换更大模型，掩盖数据错误；只保留最终文本，无法恢复原证据。

**微练习：** 给出“文档缺失、检索遗漏、生成误读”三次故障。验收：设计最小对照实验，让每次只改变一个环节。
