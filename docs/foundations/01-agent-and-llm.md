# Agent 与大模型基础

目标：能解释一次模型调用如何变成可完成任务的系统，并判断哪些问题需要模型、检索或确定性代码。以下为原创练习题，不代表任何公司的真实题库。回答是复述骨架，请用自己的项目证据补充。

### Q001 什么是 Agent，和普通 LLM 调用有何区别？

**优先级：P0**

**30–60 秒回答：** 我把 Agent 理解为围绕目标运行的闭环系统：接收当前状态，让模型选择下一步，由程序执行动作，再把结果作为观察送回。单次 LLM 调用主要生成输出；Agent 还要管理执行状态、工具和终止条件。业界用法并不完全一致，面试时应先声明定义。例如查订单可以只调用一次 API，复杂售后才可能需要动态选择查询、核验和升级步骤。[架构区分参考](https://www.anthropic.com/research/building-effective-agents)

**追问与权衡：** 谁控制下一步？若所有路径已知，工作流通常更容易测试；动态选择增加了灵活性，也增加成本和失败面。

**常见误区：** “有记忆才叫 Agent”或“用了某框架就算 Agent”都把一种实现当成必要条件。

**微练习：** 分别设计“查单个订单状态”和“处理跨订单退款争议”。验收：指出哪个决策交给模型、哪个由代码确定，以及任务如何结束。

### Q002 自回归语言模型到底在预测什么？

**优先级：P0**

**30–60 秒回答：** 典型自回归模型根据已有 token 预测下一个 token 的分布，再按解码策略选出一个并继续。token 不是固定一个汉字或一个单词。训练时常用真实前缀计算预测误差，推理时则依赖自己已生成的内容，因此错误可能沿后续输出扩散。“下一 token 预测”描述计算目标，不意味着它只能做简单补全；系统能否完成任务仍要通过实际评测判断。[生成机制参考](https://huggingface.co/docs/transformers/llm_tutorial)

**追问与权衡：** 温度改变采样分布；降低温度可能让输出更集中，但不能把错误知识变成事实，外部服务也可能引入不确定性。

**常见误区：** 把“概率最高”当成“事实最真”，或把温度为零当成跨版本可复现保证。

**微练习：** 对同一问题连续运行十次，记录格式通过率与事实正确率。验收：两项指标独立统计，并注明模型、参数、日期。

### Q003 Transformer 的 Attention 在做什么？

**优先级：P2**

**30–60 秒回答：** 注意力用当前表示生成 Query、Key、Value，根据 Query 与各 Key 的匹配程度给 Value 加权，形成包含上下文的信息。缩放点积注意力可写成 `softmax(QKᵀ/√d)V`；因果语言模型还要屏蔽未来位置。多头机制让不同投影分别建立关联，但注意力权重并不天然等于人类可验证的因果解释。[原论文](https://arxiv.org/abs/1706.03762)

**追问与权衡：** 这里讲的是标准机制。不同架构会改进位置编码、注意力布局和缓存组织，不应从公式直接推导所有模型的显存或延迟。

**常见误区：** “Transformer 完全没有顺序信息”；实际上顺序需要通过位置相关设计表达。

**微练习：** 用三段向量手算一次加权和，再遮住最后一个位置。验收：被屏蔽位置不参与有效权重分配，剩余权重重新归一化。

### Q004 Prefill、Decode 与 KV Cache 为什么影响延迟？

**优先级：P0**

**30–60 秒回答：** Prefill 处理已有输入；Decode 逐步生成新 token。对常见因果注意力模型，KV Cache 保存前面位置的 Key 和 Value，后续生成复用它们，从而减少重复计算。缓存会占显存，上下文越长、并发越高，容量压力通常越大。因此首 token 延迟和后续生成速度要分开测，不能只比较一次请求的总耗时。[缓存机制](https://huggingface.co/docs/transformers/cache_explanation)

**追问与权衡：** KV Cache、前缀缓存、最终答案缓存属于不同层次。答案缓存还要处理权限、失效时间及问题等价性。

**常见误区：** “KV Cache 保存了模型学到的新知识”或“有缓存后生成不再读取历史表示”。

**微练习：** 固定输出上限，分别测试短输入与长输入。验收：记录首 token 时间、输出 token 数、总时间；说明网络和排队是混杂因素。

### Q005 预训练、SFT、偏好优化、LoRA 分别是什么？

**优先级：P2**

**30–60 秒回答：** 预训练学习广泛的数据规律；[SFT](https://huggingface.co/docs/trl/sft_trainer) 用示范输入输出调整行为；[偏好优化（如 DPO）](https://huggingface.co/docs/trl/dpo_trainer)利用偏好信号改善输出选择。LoRA 是参数高效适配方法，常冻结基础权重、训练低秩增量，它可以用于某些微调流程，并不是与 SFT 同一维度的训练阶段。选方法时先问：缺的是知识、任务行为，还是输出偏好；再看数据质量和验证集结果。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

**追问与权衡：** 训练参数少不代表数据需求消失，也不保证每种任务都优于全量微调。应保留基础能力回归集。

**常见误区：** 把“会调用 API”归因于运行时自动更新模型参数；普通推理与应用记忆不会自动执行梯度训练。

**微练习：** 将“输出格式不稳”“内部政策每天变化”“领域术语理解差”各提出一个先做的实验。验收：说明数据、基线、成功指标和失败后的下一步。

### Q006 Prompt、RAG 与微调如何选？

**优先级：P0**

**30–60 秒回答：** 先用最小基线定位问题。说明不清或格式不稳，先改提示与校验；需要可更新、可追溯的外部证据，考虑检索；大量稳定示例能够定义目标行为时，再评估微调。三者可以组合。RAG 把外部材料带入当前上下文，微调改变模型参数；二者都要评测，不能用“上了 RAG”代替正确率证据。[RAG 原论文](https://arxiv.org/abs/2005.11401)

**追问与权衡：** 私有知识不等于必须微调。先确认权限隔离、更新频率、引用要求及每次请求成本。

**常见误区：** 把检索当成永久写入模型，或承诺微调能准确记住每条业务记录。

**微练习：** 为“每天更新的报销政策问答”写三个候选方案。验收：解释过期政策如何撤回，以及回答如何定位到有效版本。

### Q007 为什么模型会给出流畅但错误的回答？

**优先级：P0**

**30–60 秒回答：** 输出流畅只说明语言形式合理，不足以证明事实。可能是知识过时、输入缺失、证据冲突、问题歧义，也可能是检索正确而生成时误读。排查要保存用户问题、可见证据、工具结果与最终回答，找到错误首次出现的位置。减少错误需要来源核验、结构化校验、适当拒答和评测，单加一句“请勿幻觉”通常不足以形成工程约束。

**追问与权衡：** “支持引用”也不等于引用支撑结论。需核对文档是否存在、版本是否正确、具体段落是否蕴含主张。

**常见误区：** 将所有错误叫幻觉，忽略错误数据库、权限过滤或业务规则造成的问题。

**微练习：** 给回答注入一个错误日期、一个不存在的引用和一个证据不足的推论。验收：分别设计可执行的检查，不只写“让模型再检查”。

### Q008 如何为 Agent 选择模型而不只看排行榜？

**优先级：P1**

**30–60 秒回答：** 我先从目标任务采样，形成带验收标准的测试集，再比较任务成功率、工具参数有效率、延迟分位数、每个成功任务成本和失败类型。模型要在同一工具实现与可比预算下测试，并记录版本与参数。若用小模型处理简单请求、大模型处理困难请求，还要评估路由错误及升级开销，不能只看单次调用便宜多少。

**追问与权衡：** 业务风险不同，阈值也不同。订单写入应重视错误动作率，内部草稿助手可能更看重响应速度。

**常见误区：** 用十个成功演示推断线上可靠性；只在某个模型擅长的样本上比较。

**微练习：** 设计二十条示例任务，覆盖正常、缺参、冲突、工具失败与越权。验收：先写评分规则，再看模型输出；所有数字注明是本地实验。
